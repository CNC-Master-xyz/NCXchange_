# Fanuc and the ISO dialects

The Fanuc family is the largest one NCXchange reads and writes: Fanuc Series 0i, 16i/18i/21i, 30i/31i/32i and the controls that speak the same language with their own extensions, which the trade calls "ISO" or "EIA" programming: Mazak EIA, Hyundai WIA, Matsuura, Mori Seiki MAPPS (a Fanuc 31i under Mori Seiki's user interface), Doosan, Nakamura-Tome, Biglia, and the ISO mode of a Siemens (`G290`). The core is DIN 66025 G-code with Fanuc's custom macro B; everything beyond that is the machine builder's, and the reader treats it as such (`machine-builders.md`).

## 1. The program file

```
%
O0001 (2.5D FRAESEN)
N10 G0 G40
N20 G80 G90 G94 G98
N30 G54
(SIDE MILL D10 L35 SD10)
N40 T1 M6
...
N410 M2
%
```

- `%` opens and closes the file (a tape convention; the closing `%` is the file end, not the program end). A file may hold several `O` programs one after another; the control stores each under its `O` number.
- `Oxxxx` (four digits, eight on 30i) names the program; a comment in parentheses after it is the program name shown on the screen. Nakamura names the files of a two-path job by suffix (`O1000` and `O1000.P-2`). `O8000` to `O9999` are commonly reserved for the builder's programs. An NCX program without `NUMBER` takes a `NAME` of digits as its `O` number; otherwise the compiler writes the lowest number from 1 that the output file does not use, skipping `8000`..`9999`, with the WARNING CMP310 that names it, and the name stays in parentheses (D257).
- `N` block numbers are optional and need not be in order; they matter as jump targets (`GOTO 300`) and as `P`/`Q` references of the turning cycles, so no `N` may stand twice in one `O` program (section 10 rule 6, D277).
- `( ... )` is a comment, anywhere in the block. Nothing else is. Some controls restrict the character set to ASCII capitals.
- `/` or `/n` at the block start is the optional block skip: the block runs unless switch n is on.
- `M30` ends and rewinds, `M2` ends; `M99` in a main program jumps back to its first block (this is how bar-work programs loop). `M0` stops, `M1` stops when the optional stop switch is on.
- Subprograms are `O` programs of their own (after the main program's `M30` in the same file, or in their own file) that end with `M99`; `M98 P0100` calls, `M98 P0100 L3` calls three times (older form `M98 P30100`: three times program 0100), `M99 P30` returns to block 30 of the caller, and in a section no block of the file calls to block 30 of that section (D221). `M198` calls a program from external memory, where the code itself sits in parameter 6030 and a builder may set another one (Nakamura `M200`, which leaves `M198` a wait code of `M100`..`M199`), so the machine configuration carries it and a machine that names none has no external call (D322); `G65 P9010 A1 B2` calls a macro with letter arguments (section 7).
- One `G` per group. One `M` code per block is what every control accepts; three need bit 7 (M3B) of parameter 3404, five on the 30i-B bit 5 (M5B) of parameter 11630, and a builder may restrict which codes combine, so the machine file carries the number and the list (`[format] m_codes_per_block`, `m_codes_combinable`; section 10 rule 5, D339). The words in a block execute together; `S` and `M3` in a motion block start the spindle before the motion.

## 2. Numbers

- Decimal point programming: `X70.` (trailing dot) and `I-.534` (leading dot) are normal output of CAM systems and must be accepted and, on the writing side, may be written that way or padded (`70.0`), per the `[format]` table of the machine configuration.
- A number without a decimal point is, on a control with "calculator-type decimal point input" off, a count of least input increments (`X70` = 0.070 mm). Modern machines have the calculator type on, and every CAM program writes points, so the readers take `X70` as 70 mm; a machine flag for the other behaviour is a matter for the configuration.
- Angles in degrees, rotary axes usually modulo 360 with a roll-over setting that decides the direction of the shortest way.
- Feed `F` per minute or per revolution, in mm or inch per the units; `S` in rpm or m/min under `G96`.

## 3. Modality and the G groups

Every G belongs to a group; one value per group is active until another G of the same group appears. Group 01 comes up and resets to `G0` unless bit 0 of parameter 3402 selects `G1`, so a block with axis words before the source writes a code of group 01 moves at rapid (D242). The groups that matter for the readers:

| Group | Codes | Meaning |
|---|---|---|
| 01 | `G0 G1 G2 G3`, `G33` (thread), `G73 G74 G76 G80..G89` (cycles belong to group 09 on mills) | motion |
| 02 | `G17 G18 G19` | plane |
| 03 | `G90 G91` | absolute or incremental (systems B and C; system A lathes use `U W` addresses instead) |
| 05 | `G94 G95` (mill; lathe B and C), `G98 G99` (lathe system A) | feed per minute or per revolution |
| 06 | `G20 G21` (`G70 G71` in lathe system C) | inch or metric; switched only at the start of a program, so the compiler writes the code in a block of its own at the start of each program and a change after the first motion is the ERROR CMP313 (D283) |
| 07 | `G40 G41 G42` | cutter radius compensation |
| 08 | `G43 G44 G49` | tool length offset (mills) |
| 09 | `G73 G74 G76 G80 G81..G89` | canned cycles (mills); `G80` or any code of group 01 cancels (D247) |
| 10 | `G98 G99` | return to the initial level or the R level after a cycle (mills; the same numbers mean feed mode on lathe system A) |
| 12 | `G54..G59`, `G54.1 Pn` | workpiece coordinate system |
| 13 | `G61 G62 G63 G64` | exact stop, tapping, cutting mode |
| 14 | `G66 G67` | modal macro call |
| 16 | `G68 G69` | coordinate rotation (mills); on the Mori Seiki NT the same numbers are the balance cut of turret 2 |
| 17 | `G15 G16` | polar coordinate command |
| 00 | `G4`, `G10`, `G28 G30`, `G52`, `G53`, `G65`, `G92` (`G50` in system A), `G5.1`, `G8`, `G68.2`, `G53.1`, `G43.4`, `G43.5` | one-shot |

The reader keeps a source-side state of every group (its own small virtual machine) so that a block with only coordinates gets the verb of the active group 01 code, the absolute or incremental words of group 03, and so on. The compiler writes a G only when the group changes, unless the configuration asks for the G on every block.

Lathe G-code systems: Fanuc lathes come in three G-code systems selected by a parameter. System A (Nakamura, Doosan, Mori Seiki in the corpus): no `G90`/`G91`, incremental by `U W H V` (X Z C Y), `G98`/`G99` feed per minute or per revolution, `G50` for the spindle limit and the coordinate set, `G90`/`G92`/`G94` are the simple turning, threading and facing cycles. System B (Biglia): `G90`/`G91`, `G94`/`G95`, `G92` for the limit and the coordinate set, cycles `G77`/`G78`/`G79`. System C: like B with `G70`/`G71` for inch and metric and cycles `G20`/`G21`/`G24`. The multiple repetitive cycles `G70`..`G76` of the systems A and B are `G72`..`G78` in system C (`G70` finish becomes `G72`, `G71` rough OD `G73`, `G72` rough face `G74`, `G73` pattern repeat `G75`, `G74` `G76`, `G75` `G77`, `G76` `G78`), the coordinate set `G50` of system A is `G92` in B and C, and the feed modes `G98`/`G99` of system A are `G94`/`G95`; the drilling cycles `G80` to `G89` carry the same numbers in all three systems, so the `AXIS` rule is system-independent. The system is selected with bit 6 (GSB) and bit 7 (GSC) of parameter 3401, and B and C need the matching option. The machine configuration carries the system (`gcode_system` in `[machine]`) and the readers select their tables by it; the cycle catalogs stay in system A numbers and the readers and compilers translate (D174).

## 4. Motion and frames

- `G0` rapid, `G1` at `F`, `G2`/`G3` arcs with the end point and `I J K` (center, incremental from the start point, in the plane of `G17`/`G18`/`G19`) or `R` (radius; negative for the arc over 180 degrees; a full circle needs `I J`). A centre word of the plane that is left out is 0 (`I0`, `J0` and `K0` can be omitted), so the arc turns about a centre on that axis of the start point (D241). A third axis in the arc block makes a helix. With `I J K` and `R` in one block the arc of `R` takes precedence and `I J K` are ignored (FANUC 30i-B B-64484EN, cnc-manuals p. 80, Limitation); NCX keeps an `ARC` with both `CENTER` and `R` an ERROR, so the reader writes such a block in the `R` form with a WARNING (D186).
- `G90`/`G91` modal (B, C, mills). `G91 G28 Z0` is the idiom for a reference point return of Z (the `0` is an incremental distance of zero on the way to the reference point); `G28 U0 W0` the lathe form; `G30 P2` the second reference point. The words of `G28` and `G30` are the intermediate point, reached at rapid before the return: only an incremental 0 means no intermediate move, while an absolute word, `0` included, moves there first, and an address without an incremental twin is always absolute, so `G28 B0` of system A moves B to 0 on the way (D243).
- `G53` in the block: machine coordinates for that block, also with macro variables (`G53 X#528`). The move is at rapid traverse whatever group 01 holds, and `G53` is effective in its own block alone and leaves group 01 as it was; it wants an absolute value, and an incremental one makes it ignored (D242). `G53.2` is the separate machine-coordinate positioning at a feedrate.
- `G54`..`G59` workpiece coordinate systems, `G54.1 P1`..`P48` (or `P300`) the additional ones; `G10 L2 P1 X.. Z..` writes them from the program (a data setting the reader keeps as `RAW`).
- `G52 X Y Z` local coordinate system (a shift inside the active `G54`); a new `G52` replaces the old one, `G52 X0 Y0 Z0` cancels.
- `G92 X Z` (B, C) or `G50 X Z` (A) declares the current position to be these coordinates without moving; `G50 C0` after `G28 H0` is the common C-axis reset before polar interpolation.
- `G68 X Y R30` rotates the coordinate system about a point, `G69` cancels; `G51.1 X0` mirrors, `G50.1` cancels; `G51 P scale`.
- `G68.2 X Y Z I J K` tilted working plane by Euler angles (`P` selects other angle conventions), `G53.1` positions the rotary axes to it, `G69` cancels; `G68.1` rotates the coordinate system about an axis (3D coordinate conversion, on Mazak and Mori Seiki).
- `G43 H1` tool length offset plus, `G44` minus, `G49` cancel; `G43.4` tool center point control (type 1), `G43.5` (type 2, with the tool vector as `I J K`); `G41.2` 5-axis radius compensation on Mazak.
- `G41`/`G42` `D1` cutter compensation, `G40` off, applied from the motion of the same block.
- `G12.1`/`G13.1` polar coordinate interpolation (face milling on a lathe with X and C as Cartesian), `G7.1 C30` cylindrical interpolation, `G7.1 C0` off; the letter is that of the rotary axis of the workpiece holder (D146), and under `G7.1` an arc takes `R` only, never `I J K`, so an `ARC` with `CENTER` under `CYLINDER` is the ERROR CMP317 (D143). Builders alias them (`G112`/`G113`, `G107`).
- `G4 X1.` dwell in seconds: `X` (and `U` on lathes) with a decimal point is seconds whatever the increment system and parameter 1015#7; `G4 P1000` and `X`/`U` without a decimal point count `[machine] dwell_increment` (0.001 s with IS-B). The compiler writes `G4 X` with a decimal point (D159; 30i-B B-64484EN p.188).
- `G5.1 Q1` AI contour control on, `Q0` off; `G5 P10000` high precision mode; `G8 P1` look-ahead; `G61` exact stop, `G64` cutting mode (`PATH_MODE`, D349). No per-program form carries a tolerance: chapter 20.1 names none, and the only parameters that hold one in the input unit belong to nano smoothing, 19581 and 11682/11683 (levels 1 and 10), with 11684/11685 the rotary tolerances of nano smoothing 2. So NCX `TOLERANCE` reaches Fanuc only as the on and off switch; the compiler reports the value it cannot write as CMP015, naming `[tolerance] held_in` (D367). `G05.1`, `G08` and `G05` stand in a block of their own, with no other G code (30i-B B-64484EN p.635-636; parameters B-64490EN-05 p.654-655).
- `G5.1 Q1 R_` selects the precision level 1 to 10 of the optional machining condition selecting function, `G5.1 Q3 R_` the smoothing level of the machining quality level adjustment; the level picks a point between a level-1 and a level-10 parameter set (13610 to 13625 and following for AI contour control, 11682/11683 for nano smoothing), whose ends and direction are the machine's calibration; 11687 (AI contour control) and 11686 (nano smoothing) give the level a reset or power-on restores, 0 keeping it, and a level once set stays after the mode ends. The level is no carrier of the `TOLERANCE` value: NCX does not write `R`, and `fanuc-mill-30i.toml` has no levels table (D368; 30i-B B-64484EN p.650-651, B-64490EN-05 p.655, 729-731).
- `G96 S200` constant surface speed with the limit `G50 S3000` (A) or `G92 S3000` (B, C), `G97 S1500` rpm. These are family codes: where the spindle table of a role lacks `VC`, `CSS_OFF` or `RPM_MAX`, the compiler writes them (D258).
- Polar coordinates `G16`/`G15` with the radius in X and the angle in Y: converted to Cartesian by the reader.
- Chamfer and corner rounding attached to a motion block, `,C2` and `,R4` (with a comma), are expanded by the reader into the line and arc they stand for.

## 5. Tools

The `T` word means different things per machine kind, and the two-word model of NCX (`PRELOAD`, `TOOL`) covers all of them:

- Mill with a magazine: `T5` alone brings tool 5 to the change position (preload); `M6` performs the change to the preloaded tool; `T4 M6` in one block changes to 4 directly (the control preloads and changes). `T5` after the `M6` in the same block is illegal on most controls. `M6` without any preload is an error in the source.
- Lathe with a turret: `T0404` indexes station 4 and activates offset 4 in one word; `T0656` is station 6 with offset 56; `T0100` cancels the offset of station 1; six-digit forms `T001001` exist on 120-tool ATCs. A `T` word alone in its own block moves the axes by the difference of the offsets, at rapid under `G0`, which is why the builders recommend writing it inside a `G0` block; the reader emits the offset change and no motion.
- Which form a lathe `T` word is, the tool holder decides (D219): the word belongs to the holder whose `channel` is the channel of the program, else to `default_holder`; on `default_holder` the `[tool_change]` templates are tried first (Mori Seiki `T9001` is the preload of a magazine tool), and every other `T` word of a lathe is the turret form above, with the role of its holder on the `TOOL`.
- Mill-turn ATCs wrap the change in a builder macro: Nakamura `G340 T0101. A02.` (change to 1 with offset 1, prepare 2), Mori Seiki `T9001` then `G361 B0 D1.`, DMG on Siemens `T="NAME"` then `TC(...)` (`machine-builders.md`).
- `G43 H` and `D` carry the offsets on mills; on lathes the offset is inside the `T` word. `H` and `D` of the same tool usually have the same number (a CAM habit, not a rule).
- A tool change applies no length offset of its own: `T1 M6` without `G43 H` leaves the tip one tool length below the programmed point. The compiler writes no default `G43 H` (the M-series `T` has no relation to `H`), and the first tool-axis motion after a `TOOL` without `OFFSET:LEN`, `OFFSET` or a named point's register is the WARNING CMP342, once per tool change, naming the tool; `[tool_change] length_offset_by_macro = true` silences it on a machine whose change macro applies the length (D389, R1-13).
- Measurement points (D373, D375): `H` and `D` index a flat register pool, and the M-series `T` has no relation to them, so a point's registers come from the machine file's `[tool_points] form = "registers"` (a `[[tool_point]]` row, the shop's step rule, or `H99`/`D99` under tool management for point 1). Whether `H` and `D` share one pool is the offset memory type (A or B one pool, C two), and whether geometry and wear are separate is parameter 8136 bit 6 on the 0i generation; NCX writes the register number the machine file gives and derives nothing from it under any memory type. `TIP_OFFSET` and `POINT_RADIUS` are never written: a program can only select a register or overwrite one with `G10` or a macro variable, which changes machine state that survives the program.

Spindles: `M3`/`M4`/`M5` with `S`. Fanuc has one `S` address; on a machine with several spindles the `S` belongs to the spindle whose M code is in the same block (Nakamura: `M88 S1000` for the rotary tool, `M3 S500` for the main spindle), otherwise to the spindle selected last. The compiler therefore writes speed and direction together; the reader assigns a bare `S` with its source-side state. Doosan selects the spindle with a `P` suffix (`M03 P11`, `M03 P12`), Mori Seiki and Nakamura with offset M numbers (`M203`, `M53`). Where a table lacks `VC`, `CSS_OFF` or `RPM_MAX`, the compiler falls back to `G96 S`, `G97` and `G50 S` (A) or `G92 S` (B, C, mill) (D258).

## 6. Cycles

Mill canned cycles are one block that defines and calls: `G81 G99 Z-21.732 R5. F565` drills at the current X Y to Z-21.732 (absolute under `G90`), starting the feed at `R5.` and returning to R (`G99`) or to the initial level (`G98`); every following block with a position calls the cycle again at that position; `G80` or any code of group 01 (`G0` to `G3`) cancels and leaves the same state (D247), so a group 01 code and a cycle code never stand in one block, and a control may keep the `R` level and the initial point after a group 01 cancel that `G80` clears. `G82` adds a dwell `P` (milliseconds), the only dwell of the mill drilling codes besides `G84` and `G89` (`G73`, `G81`, `G83`, `G85` and `G86` have none, B-64484EN-2 p. 56, 61-84), so a `DRILL` with a dwell is written as `G82`, a `REAM` with one as `G89` (the `dwell_native` of the `REAM` entry, read back as `REAM` with `CYCLE_DWELL`), and `PECK`, `CHIP_BREAK` and `BORE` drop a dwell other than 0 with a compiler WARNING (D177); the lathe catalog keeps `P` on every entry, `G83`/`G87`, `G84`/`G88` and `G85`/`G89` all taking it. `G83` pecks with `Q`, `G73` chip-breaks, `G84` taps (`M29 S` directly before it makes it rigid, which is the `before` line of the `TAP` entry of the catalog and part of `CYCLE=TAP`, D256; an `S` word or an axis motion between the two alarms PS0203, and a `G84` without the line is tapping with a compensating chuck, `CYCLE=TAP_COMPENSATING` (D359); the pitch is `F`, or `F`/`S` in per-minute mode), `G85` reams, `G86` bores, `G76` fine bores with a shift, `G74` left-hand taps, `G87`..`G89` back boring and variants. `K3` on the cycle block repeats it three times at incremental steps under `G91`. `Q` is the peck only on `G73` and `G83`, and on `G74` and `G84` where the machine declares peck rigid tapping (`[cycles] peck_rigid_tapping`, D388 item 11); `PECK` on `G76`, `G87`, `G88` or `G89`, or on `G74`/`G84` without the option, is the compiler ERROR CMP393. `Q` is modal data the native cycles share, so the compiler never writes a `G73` or `G83` that relies on an inherited `Q` (CMP394), and a native parameter of `CYCLE:FANUC` is one letter `A`..`Z` (CMP395) (D279). The control counts `Q` from its own `R` plane while NCX counts `PECK` from `SURFACE`: the compiler writes `Q` = `PECK` unchanged and names the shift once, at the block that defines the cycle, as the INFO CMP387, none where the gap is zero (D355). A cycle word the entry maps to no address and no rule carries is CMP385, except `CYCLE_DWELL=0` and `PECK=0`, the behaviour the control has anyway, which are dropped silently (D362). The reader converts `R` and `Z` to the absolute `CLEARANCE` and `DEPTH` of NCX and keeps the modal call behaviour by emitting a `CYCLE_CALL` per position. `SURFACE` is `R` minus `[cycles] surface_clearance`, `0` where the machine file leaves the key out (D158). A `P` on `G73`, `G81`, `G83`, `G85` or `G86` of a mill is ignored by the control and dropped by the reader with the WARNING RDR122, and `G89` reads as `REAM` with `CYCLE_DWELL` (D177). Outside `G17` the drilling axis of a mill depends on parameter 5101#0 FXY (0 always Z, 1 by the plane and the axis address); the reader derives it from the plane and warns with RDR120 (D157). A one-shot cycle `G70`..`G76` is followed by `CYCLE=OFF` after its `CYCLE_CALL`, for which a compiler writes nothing (D224).

Lathe drilling cycles: the canned-cycle group of a lathe holds `G80` and the two triples `G83`/`G84`/`G85`, which drill along Z with X and C as the positioning axes, and `G87`/`G88`/`G89`, which drill along X with Z and C (NCX `AXIS=X`); the two triples are otherwise identical in function, all six take a dwell `P` at the bottom, `G83` and `G87` peck when `Q` stands and run a plain drilling cycle with a rapid retract from the bottom without it, `G84` and `G88` reverse the spindle, and `G85` and `G89` feed in, dwell and feed back out at twice the cutting feedrate. `G81` and `G82` stand in the lathe list only as FS15 format codes and `G86` not at all, so `DRILL_DWELL` and `BORE` have no lathe code. Whether `G83` pecks at high speed or retracts fully is bit 2 (RTR) of parameter 5101, which is why `CHIP_BREAK` belongs in the machine file; Mori Seiki's `G83.5`/`G87.5` and `G83.6`/`G87.6` name the two behaviours without the parameter. `cycles/fanuc-lathe.toml` carries the entries, the two triples as entries of one name that differ by `for_axis` (D160). `R` of a lathe drilling cycle is the signed incremental distance from the initial level, always a radius: the reader writes `CLEARANCE` = initial level + `R` (+ 2·`R` on an X axis under `DIAMETER=ON`) and keeps the block `RAW` where the initial level is not known, and the compiler writes `R` back from `CLEARANCE` and the initial level of the run (CMP396 where that is not known). The depth word follows its address in system A (`Z`/`X` absolute, `W`/`U` incremental from `R`) and `G90`/`G91` in systems B and C; no machine key, since `RAB`/`RDI` apply only to the Series-15 format. On a mill under `G91` `R` counts from the initial level and `Z` from `R` (D248). Turning cycles: `G90` (OD/ID), `G92` (one thread pass, NCX `THREAD_PASS`), `G94` (face) in system A (`G77`/`G78`/`G79` in B, `G20`/`G21`/`G24` in C, D174) are modal like the drilling cycles, a following block with only `X`, `Z`, `R` (or `U`, `W`) repeats them; `G70`..`G76` (finish, rough OD, rough face, pattern repeat, face cut-off, OD groove, the multiple thread cycle `G76`, NCX `THREAD`, D161) are one-shot blocks; in system C they are `G72`..`G78` (D174). `G70`..`G73` name the block range of the finishing contour with `P` and `Q`, which NCX carries as a subprogram section referenced by `CONTOUR=`; `G74` and `G75` take `P` as the step along the second plane axis and `Q` as the step along the first, and `G76` takes `P` and `Q` as thread data, so those three carry no contour (D176). The NCX names of the two the documents had none for are `PATTERN_REPEAT` for `G73`, with a contour, and `FACE_GROOVE` for `G74`, without one; both belong to the lathe catalog, since `G73` and `G74` are `CHIP_BREAK` and left-hand tapping on a mill (D176).

Addresses of the turning cycles (lathe manual of the 30i/31i/32i-B; D175, D176). The simple cycles are one block:

| Cycle | Block | Addresses |
|---|---|---|
| `G90`, `G92`, `G94` | one | `X(U)` `Z(W)` end point of the pass, `R` the taper (a radius value, signed), `F` the cutting feed on `G90` and `G94` and the thread lead on `G92`; `Q` on `G92` shifts the thread start angle in 0.001 degree steps for a multi-start thread |

The multiple repetitive cycles are written as two blocks, and the same letter means different things in the two:

| Cycle | First block | Second block |
|---|---|---|
| `G71`, `G72` | `U(Δd)` or `W(Δd)` depth of cut, `R(e)` retract | `P(ns)` `Q(nf)` contour block range, `U(Δu)` `W(Δw)` finishing allowances, `F` `S` `T` |
| `G73` | `U(Δi)` `W(Δk)` relief, `R(d)` number of divisions | `P(ns)` `Q(nf)` contour block range, `U(Δu)` `W(Δw)` allowances, `F` `S` `T` |
| `G74`, `G75` | `R(e)` return amount | `X(U)` `Z(W)` end point, `P(Δi)` `Q(Δk)` the two infeed steps, `R(Δd)` relief at the cut bottom, `F` |
| `G76` | `P(m)(r)(a)` finishing repeats, chamfer and tool angle, `Q(Δdmin)` smallest cut, `R(d)` allowance | `X(U)` `Z(W)` end point, `R(i)` taper, `P(k)` thread height, `Q(Δd)` first cut, `F(L)` thread lead |

`G70`, the finishing cycle, is one block: `P(ns)` `Q(nf)`, the contour block range.

The manual warns for `G71`, `G73`, `G74` and `G76` that the same address means different things depending on which other words stand in the block, which is why the reader keeps a cycle block with a word its catalog entry does not map as `RAW` (D5). NCX maps the taper `R` of the simple cycles as the catalog word `TAPER`, a parameter name of the entry that the parser takes in a block whose `CYCLE` is a catalog name (D114), and the thread lead `F` of `G92` and `G76` as `PITCH` (D175); since `R` is modal data of the three cycles, a repeat block with a new `R` is a new `CYCLE` block; the other words of `G71`..`G76` and the two-block form wait for a later catalog decision. The compiler writes a `G70`..`G73` with its `CONTOUR` as `G71 Pp Qq` followed by the blocks of the contour section inline, the first numbered `Np` and the last `Nq` after the greatest numeric label of the program (D277), never as an `O` program; a later cycle of the program repeats `P` and `Q` alone, and a second program gets its own copy. The first block writes `G00` or `G01`, and for `G71`/`G72` only the plane axes it moves: `X` alone (`Z` for `G72`) is type I, both are type II, which only a machine with `[cycles] contour_type_ii` takes (else CMP389); a first block of `G71` that does not move `X` is alarm PS0325 (CMP390), one that is no `RAPID` or `LINE` CMP392, and a contour holding anything but `G04`, `G00`..`G03` and a `LABEL`/`JUMP` inside the range CMP391. The later blocks are written from an unknown motion state, and after the section every code they wrote is unknown (D278).

## 7. Custom macro B

- Variables `#1`..`#33` are local to a macro call level (levels 0 to 5, the main program being 0; a macro call raises the level, a local that received no argument starts vacant, and `M99` restores the caller's values, while a subprogram call with `M98` does not change the level and so shares the caller's `#1`..`#33`, D148), `#100`..`#199` common (cleared at power-off), `#500`..`#999` permanent, `#1000` and above system variables (`#5021`..`#5025` current machine position, `#5041`.. workpiece position, `#4001`.. modal G codes, `#3000` alarm, `#3001` timer, `#2001`.. and `#11001`.. offset and wear registers on lathes: `#11099` is the Z wear register 99 in the Nakamura transfer program). `#0` is empty (vacant).
- Expressions in brackets: `#1 = [#2 + 3.5] * SIN[#3]`; functions `SIN COS TAN ATAN SQRT ABS ROUND FIX FUP LN EXP`; operators `+ - * / MOD`, comparisons `EQ NE GT GE LT LE`, logic `AND OR XOR`. `ATAN[#1]/[#2]` (also written `ATAN[#1,#2]`) takes its arguments in the order NCX `ATAN2` does, the ordinate first, but gives 0 to 360 degrees unless bit 0 (`NAT`) of parameter 6004 is 1, where it gives -180 to 180 as NCX does; the program does not carry that bit, so the reader and the compiler can convert the range only once the machine file says which range the control uses (D119). An argument out of range is the alarm `PS0119`, which is the control's form of the NCX ERROR for a function without a real result.
- Flow: `GOTO n` (to block `Nn`), `IF [cond] GOTO n`, `IF [cond] THEN #1 = 2`, `WHILE [cond] DO1` ... `END1` (three nesting levels), `M99` returns from a macro. A `REPEAT` with `TIMES` is a counter and `IF GOTO`: the counter of its nesting depth from `[variables] repeat_counters` is cleared at the start of the program, counted up before the `IF [#149 LE k] GOTO n` and cleared after the loop and by every `JUMP` that leaves the section, so a later arrival starts afresh (D213, D280; CMP314 without a counter, CMP315 where the program uses it).
- Variables hold numbers only: an NCX `==` or `!=` between two strings has no Fanuc form and is the ERROR CMP316 (D169).
- Calls: `G65 P9010 A1. B2. Z-5.` calls program 9010 once with letter arguments; `G66 P9010` makes it modal (called after every motion block, like a cycle) until `G67`; the letters map to local variables by the standard table: `A`=#1, `B`=#2, `C`=#3, `I`=#4, `J`=#5, `K`=#6, `D`=#7, `E`=#8, `F`=#9, `H`=#11, `M`=#13, `Q`=#17, `R`=#18, `S`=#19, `T`=#20, `U`=#21, `V`=#22, `W`=#23, `X`=#24, `Y`=#25, `Z`=#26 (`G`, `L`, `N`, `O`, `P` cannot be arguments). NCX names them `V1`..`V33` and `#100` becomes `V100`, because `#` is not a legal character in an NCX name.
- Builder macros are called through G codes bound to programs (`G340`, `G411`, `G300` on Nakamura; `G361` on Mori Seiki) or through M codes that run hidden subprograms; the reader cannot see inside them, which is why the machine configuration and the reader rules decide what they mean.

## 8. Several paths

A two-path lathe runs one program per path (turret, or head and turret). The paths synchronize with wait M codes in a parameter-defined range (`M100`..`M199` on Nakamura, `M101`..`M197` on Mori Seiki): both programs must reach the same M number before either continues. On three- and four-path machines a `P` word names the participants as a path list (`P12`, `P123`) or a bitmask (`P3` = paths 1 and 2, `P7` = all), selected by a parameter; without `P` all paths wait. `M199` at the start synchronizes the program start on Nakamura. The same mark may be used many times in program order. Balance cut (`G68`/`G69` on the Mori Seiki NT) lets two turrets cut the same contour from both sides.

## 9. Rules for the reader

1. Resolve every block against the source-side state: verb from group 01, which starts at `G0` (D242), absolute or incremental from group 03 or the `U W` addresses, plane from group 02, feed mode from group 05 or `G98`/`G99` on system A.
2. `T`, `M6` and the offsets per section 5; `S` binds to the spindle of the M code in the same block, else to the last selected spindle.
3. `G91 G28 Z0` and `G28 U0 W0` are `HOME`; `G30 P2` is `HOME POINT=2`; an absolute word of `G28` or `G30`, `0` included, is the intermediate point and becomes a `RAPID` to it in front of the `HOME` (D243). `G53` is `FRAME=MACHINE` on the block and `RAPID`, whatever group 01 holds (D242).
4. An `O` section a block of the file calls is a subprogram; one that no block calls is a program when it holds an `M30` or `M2`, a skipped one included, and a subprogram otherwise, except that where no section of the file is a program the first uncalled one is, with an INFO naming that reading (D210). `M99` in the main program is a jump to a label after the header; `/M30` is `SKIP JUMP=END`; `GOTO` to a block below `M30` and back becomes a section in front of `PROGRAM=END` behind `JUMP=END`. A program that has no end at all, one that runs into the closing `%`, is ended after its last block with a WARNING, as a Klartext program without `M30` is (D211).
5. `G81`..`G89` define and call; following position blocks call; `G80` or any `G0` to `G3` cancels (D247); `R` and `Z` become absolute `CLEARANCE` and `DEPTH`; `K` repeats expand. A block with a group-01 code and a drilling cycle code (`G73`, `G74`, `G76`, `G81`..`G89`, mill and lathe) is not a cycle: the control executes the group-01 code and cancels the cycle as `G80` does, moving with the block's axis words, the hole-bottom Z included (B-64484EN-2 p.105). The reader keeps it `RAW` with the WARNING RDR121 and writes no `RAPID` guess, since the control's handling of `R`, `Q`, `P` and `K` in a `G0` block is not documented; afterwards the motion is the block's group-01 code, no cycle is active (`CYCLE=OFF` after the `RAW` block where one was written), `R` and `Z` are cleared, and a rigid-tapping line in front of it gets no `TAP` mark (D386).
6. `G52` replaces the previous `G52`, so the reader writes `SHIFT=RESET` before the new `SHIFT`. In a `G52` block `U` and `W` are the lathe spelling of that absolute local origin, not increments, so rule 1 does not apply to them and the reader writes absolute `SHIFT` words (D117).
7. `G10`, `G65`/`G66` calls of unknown macros, probing (`G31`, `G38`), builder G macros not in the configuration: `RAW` with a WARNING, never dropped.
8. Numbers are taken as written; a trailing or leading dot is accepted.
9. The `before` line of a catalog entry belongs to the cycle (machine-config 6, D256). Fanuc gives three ways into the mode it switches on: the line in front of the cycle block, the line in the same block as the cycle command, and the control parameter that needs none, which is the entry whose `before` is `""`. The control names `M29 S` "before a tapping command" and forbids only an `S` command or an axis movement between `M29` and `G84`, alarm PS0203 (B-64484EN-2 p.103-104; manual audit 2026-10-26, section 3), so the reader walks back from the cycle block over the blocks with neither an `S` word nor an axis word and ends at the first block with one, which may hold the line as well: `M29 S500` / `M8` / `G84` and `Z10. M29 S500` / `G84` read like `M29 S500` directly in front of the `G84`. The walk ends without the line at the head of a program, at `G80`, a canned-cycle code or a code of group 01, which cancel the mode (B-64303EN-1 p.927, 10.13.16.8), and at `M2` or `M30`, whose reset cancels it (B-64484EN p.297; B-64484EN-2 p.103); a block with the entry's own native code, a `G84` of the same run, ends it too and leaves the reading to that cycle block. It ends unseen, and the cycle stays `RAW` with that reason (D5), at a block skip, a block a jump enters (the cycle block among them), a call, a return, a macro branch, the head of a section a block of the file calls, a `T` word, `M6`, `G43`, `G44`, `G49` (the manual neither allows nor forbids them and the control does not cancel the mode for them on its own, D383), a spindle code `M3`, `M4`, `M5` or `M19` between the line and the `G84`, which the machine's PMC handles and which may raise an alarm or drop the rigid mode, with a reason that names the code (a spindle code before the line, `S500 M3` / `M29 S500` / `G84`, is unaffected; D385), and at a block that carries the line together with a cancel code (`G0 Z10. M29 S500`), since the manuals state the group-01 cancel only after tapping (B-64303EN-1 p.927) and the one builder example of a move in the M29 block has no G code (Mori NTX1000SZM p.281-282), so `Z10. M29 S500` stays a valid place for the line (D384); a line block that ends `RAW` does not count, and the cycle then stays `RAW` with a reason that names it. The line is read into `CYCLE=TAP`, and the `S` becomes `RPM` only where it differs from the running speed. The mode then holds for the run of the cycle, which `G80` or a code of group 01 ends (rule 5), and an `M29` inside a running tapping cycle alarms PS0204, so every cycle block of one run is the same `CYCLE=TAP`. A `G84` that the line reaches in none of the three ways is tapping with a compensating chuck, another machining than the entry names: `CYCLE=TAP_COMPENSATING`, the entry of the same word set with no `before` key (D359). Where a jump enters the cycle block or a block of the walk, or the cycle block begins a section a block of the file calls, the reader decides from the flow, as the control does: the mode is in force when the line stands directly before every block that reaches the cycle block, before each `CALL` of the section the block begins, before every jump to the label a jump enters and before the block in front of it where the flow also runs through; a jump back from the run of the same cycle decides nothing. The cycle then reads as `CYCLE=TAP`; where one path reaches it with the line and another without, its blocks stay `RAW` with that reason, and where no path has the line it is `TAP_COMPENSATING` (D360). The line is the machine's, not the catalog's: a machine file overrides it with its builder's code (Mori Seiki `M329 S{rpm}`), and a Fanuc-family machine that names none writes `M29`, the Fanuc standard (parameter 5210 = 0; D361).

## 10. Rules for the writer

1. Write `G0`/`G1` only when the verb changes and `G2`/`G3` on every arc block, the Fanuc family value of `[format] motion_code` ("change" and "every_block" are the other forms, D299); write `G90` once in the header, which is required because parameter 3402#3 sets the power-on state, and write `G91` blocks for incremental words; no machine key chooses otherwise (D282 (b)). A block that mixes absolute and incremental words, a `G53` block and a canned-cycle position are written absolute from the point reached; for canned-cycle positions that is an NCX simplification, not a rule of the control.
2. Write `M3 S1000` in one block, never `S1000` alone after another spindle's M code (section 5).
3. Program end from `program_end` (`M30` or `M2`); subprograms after it as `O` programs ending with `M99`, or as separate files when the machine wants that; a `JUMP` to the label after the header is written back as `M99`, the loop of a bar-work program, where every jump to that label is unconditional; `M99` takes no condition, so a conditional one keeps the label's `N` and `IF [ ] GOTO` (D210).
4. Wait marks from the `[sync]` table with the path form the machine uses (list or bitmask).
5. Decimal point on every real number per `[format]` (`decimals`, `trailing_zeros`); comments in parentheses, transliterated to ASCII under `comment_charset`, which defaults to "ASCII" on every family and takes "ASCII" or "UTF-8" (machine-config 2, D263); at most `[format] m_codes_per_block` M codes in a block, 1 by default (D339). The first function that does not fit and every later one stand on lines of their own after the block, in their order, or all functions stand on lines before it where the block moves, so the state is set before the motion (language 5 rule 3); a spindle stop and the coolant OFF come before the named functions and a spindle start after them, so a chuck never opens while its spindle turns (NTX1000SZM p.257 note 3). A comment text that holds `(` or `)` is written with `[` and `]` and a WARNING per comment (CMP312), because its first `)` would end the comment and the rest of the line would run as code (D390, R1-14). Still open: the 30i-B manual is to be checked for an alarm on `[` `]` inside a comment before release, and the page noted here (D390).
6. Numbers, names and file names per `[format]`; block numbers per `format.block_numbers`. A numeric `LABEL` keeps its number; identifier labels and the end of a conditional `JUMP=END` are numbered above the greatest numeric label of the `O` program, in file order, the end last, and `block_numbers` skips every label number. No `N` may repeat within one `O` program, and the compiler checks this (CMP318, D277).
7. The `before` line of a catalog entry stands in its own line directly before the cycle block, `M29 S500` before `G84 G99 Z-20. R5. F750`, and once per run of the cycle, since an `M29` inside a running tapping cycle alarms PS0204 (machine-config 6, D256). The line is the one of the compiled channel's entry, a `[[cycle]]` table with `channel` over the channel-less one (D361, D377). `TAP_COMPENSATING` is `G84` without the line, and a run of `TAP` and one of `TAP_COMPENSATING` on the same `G84` are separated by `G80` (D359).
8. The units code, `G20`/`G21` (`G70`/`G71` in system C), in a block of its own at the start of every program, before any coordinate-system or offset setup, whatever `units_default` says, which stays a reader-side assumption (D283).

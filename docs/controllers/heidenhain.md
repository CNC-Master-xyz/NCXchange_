# Heidenhain Klartext (iTNC 530, TNC 640)

Heidenhain controls are programmed in Klartext (conversational format): every block is a complete statement whose first word says what it is, coordinates carry their own sign and prefix, and the cycles are named definitions with `Q` parameters. NCXchange reads and writes the Klartext of the iTNC 530 and the TNC 640 (`.h` files). The DIN/ISO mode of the same controls (`%NAME G71 *`, G codes with an asterisk at the block end) and the new TNC7 syntax are not covered by version 1.0.

## 1. The program file

```
0 BEGIN PGM 2.5D FRAESEN MM
1 CYCL DEF 247 INIT. REF.PKT ~
    Q339=1 ;REF.PUNKTNUMMER
2 BLK FORM 0.1 Z X0 Y0 Z-20
3 BLK FORM 0.2 X100 Y100 Z0
4 * - SIDE MILL D10 L35 SD10
5 TOOL CALL 1 Z S1592
6 TOOL DEF 0
7 M3
...
44 M5
45 END PGM 2.5D FRAESEN MM
```

- `BEGIN PGM name MM` (or `INCH`) opens and `END PGM name MM` closes; the name is the file name without `.h`. One program per file. Blocks are numbered consecutively from 0 by the editor; the numbers are part of the text and `LBL`, not block numbers, are the jump targets.
- `BLK FORM 0.1`/`0.2` describe the blank for the graphic (kept as header information, `RAW`). The reader keeps them `RAW` in release 1 although the `STOCK` word exists, which the compiler writes back through the `[stock]` template (D351); `BLK FORM CYLINDER`, the rotationally symmetric blank and the hollow cylinder stay `RAW` as well, as every `BLK FORM` does in release 1 (D352).
- `;` starts a comment at the end of a block or a comment block; `* - TEXT` is a structuring block shown in the program outline.
- `~` at the end of a line continues the block on the next line (cycle definitions are written this way by CAM systems).
- `/` at the block start is the optional skip.
- `M30` ends the program (`M2` is accepted); `STOP` or `M0` stops, `M1` optionally. A missing `M30` before `END PGM` is tolerated by the control.
- Subprograms are `LBL 1` ... `LBL 0` sections after the `M30` inside the same program (`LBL "NAME"` from NC-SW 340 49x-01; the compiler never writes it and numbers every label within `[format] label_max`, D271); a section that stands before the `M2` or `M30`, or in a program without one, is run by the main flow as ordinary blocks at least once as well, over and above its calls (D254); `CALL LBL 1` calls once, `CALL LBL 1 REP 3` repeats the section between `LBL 1` and the call three more times (a program-part repeat, not a subprogram); `CALL PGM name` calls another file (with `Q` parameters set before the call); `FN 9`..`FN 12` jump to an `LBL` conditionally. The control keeps the remaining count of a `REP` as block state, which only `GOTO 0` or a new program selection resets, so a jump out of the repeated part may leave a count behind (D213).
- The decimal separator in the file is the comma (`X-6,964`); the writer must produce it. Newer controls accept the dot in the editor, the files still carry the comma.

## 2. Motion

- `L X+10 Y-5 Z+2 R0 FMAX M3`: line to the target; `FMAX` is rapid, `F500` feed, `F AUTO` the feed of the `TOOL CALL` block (D251), `F` modal otherwise; `R0`/`RL`/`RR` radius compensation off, left, right, on the `L` block only: Klartext offers the word on any path function, but a compensation takes effect and is cancelled only in a straight-line block, and the `C`, `CR` and `CT` dialogs have no entry for it (D345); up to two `M` functions at the end.
- Some `M` functions become effective at the start of a positioning block and others at its end, whatever their order in the block: `M3`, `M4`, `M8`, `M13`, `M14` at the block start, `M0`, `M1`, `M2`, `M5`, `M6`, `M9`, `M30` at the block end (D252). A function the machine builder adds acts as the machine manual says.
- Coordinates carry a sign (`X+10`); `IX+30` is incremental (`IX IY IZ IA IB IC`), never modal.
- `CC X+50 Y+50` sets the arc center (absolute; `CC IX IY` incremental; `CC` alone takes the current position; no form with exactly one coordinate of the plane is described, D400); `C X+70 Y+50 DR+` draws the arc about it, `DR+` counterclockwise, `DR-` clockwise; `CR X+2 Y+7 R+5 DR-` draws by radius (positive radius: arc of at most 180 degrees, negative: more); `CT X Y` a tangentially connecting arc.
- Polar: `LP PR+50 PA+30`, `CP IPA+737.956 IZ-5.4 DR+` (an incremental polar angle with an axial increment is how helices are written; `CP PA` absolute), `CC` is the pole. The path movements of a helix can be programmed in polar coordinates only, whatever its sweep: the input of `C` and `CR` is the two coordinates of the arc end point (D268).
- `LN X Y Z NX NY NZ TX TY TZ F` is the 5-axis line with the surface normal and the tool vector, used with `M128` or `FUNCTION TCPM`; with `FMAX` it is the rapid with the tool vector, which NCX reads as `RAPID` with `TX TY TZ` (D185). `LN` has no arc form, so an `ARC` with a tool vector does not compile to Klartext (D185).
- `CHF 2` chamfer and `RND 4` rounding between two motion blocks: the value of `CHF` is the distance along each line from the corner point, a feed in a `CHF` or `RND` block acts in that block alone and the feed programmed before it is valid again afterwards, and an incremental coordinate of the block after the corner counts from the corner point, the last programmed position (D255). A contour does not begin with a `CHF` block, and the corner point the chamfer cuts away is not approached. A `CHF` stands only between two straight lines; next to an arc it is invalid on the control (iTNC530 Benutzerhandbuch-Klartext 340422 p.202, D401). A `CT` after a `CHF` or `RND` is tangent to the element before it and leaves no corner for them, so the combination is redundant or an error on the control (D402). `APPR`/`DEP` approach and departure blocks (`APPR LT`, `DEP CT`...) are kept `RAW` in 1.0.
- `M91` in the block: coordinates from the machine datum; `M92` from a second datum.
- `M126`/`M127`: shortest path of rotary axes; `M128 F1000`/`M129`: tool center point control (with the feed of the compensating motion), `FUNCTION TCPM F TCP AXIS POS PATHCTRL AXIS` and `FUNCTION RESET TCPM` on the TNC 640; `M116`/`M117` rotary feed in mm/min; `M138` selects the tilting axes for `M128`; `M140 MB MAX` (or `MB50`) retracts along the tool axis to the limit or by a distance, `M140 MB MAX F..`; `M118` handwheel superimposition, `M120 LA` look-ahead for radius compensation, `M136` feed per revolution, `M137` back to feed per minute. Every program starts with feed per minute: a modal M function that is not cancelled in a later block is cancelled at program end, and the control resets the modal program information when a new program is selected, so `M136` never carries into the next program (D337).
- `CYCL DEF 32.0 TOLERANZ`, `32.1 T0.02`, `32.2 HSC-MODE:0 TA0.05`: contouring tolerance, mode (0 finish, 1 rough) and rotary tolerance. `TA` is written only while `TOLERANCE:ROTARY` is set, through the `ON_ROTARY` template of `[tolerance]`; otherwise the cycle ends with `HSC-MODE`, the safe iTNC 530 form: the control accepts cycle 32 without `TA` and inserts it as 0 when it reads the program in, and alarm 6066 forbids a rotary tolerance with the HSC filter off (D151; iTNC 530 Zyklen 606420-01 p.310, Parameter-Alarme 2003 p.309).

Poles on the output grid (D364): the compiler writes the rounded end point of `C` and picks the pole `CC` (absolute, or `IX IY` from the written start) among the nine grid points one step around the rounded centre, the one whose radius from the written start and radius to the written end agree best, with the WARNING CMP030 above `[machine] arc_radius_tolerance`, or one output step without it; the grid is searched only when the program's own pole, rounded, misses that tolerance (gap closed 2026-10-28, delegated). `CP IPA` writes no end point, since the control turns about the pole by the sweep, so its pole is the rounded centre, and the decimals of `IPA` (`ANGLE`, four by default, D366) are its one lever against the end the control computes (D365).

## 3. Frames

- `CYCL DEF 247 INIT. REF.PKT Q339=1` activates preset 1 of the preset table (the datum).
- `CYCL DEF 7.0 NULLPUNKT`, `7.1 X+60`, `7.2 Y+40`, `7.3 Z-5`: datum shift, axes in any order, an omitted axis is unchanged, a new cycle 7 replaces the previous one; `CYCL DEF 7.1 #5` takes line 5 of a datum table.
- `CYCL DEF 8.0 SPIEGELN`, `8.1 X Y` mirror; `CYCL DEF 10.0 DREHUNG`, `10.1 ROT+30` rotation; `CYCL DEF 11` scaling; `CYCL DEF 26` axis-specific scaling.
- A new definition of cycle 7, 8, 10, 11, 26 or 19, or an absolute `PLANE`, replaces the earlier one of its kind, and the transforms are reset in the reverse order of their definition: the control's own form of the chain of language 4.2 (D253). Where the replaced entry is the last of the chain the reader writes its `RESET` and the new entry; where other entries follow it, the block stays `RAW` with a WARNING, because whether the new definition acts in the place of the old one or at the end of the chain (the 7-10-7 case) is not tested on a machine (D253). The compiler never writes the case: such an entry is CMP106, and a `RESET` that removes a transform the cycle 7 of a `SETPOS` follows is CMP114. This is the end state, to be revisited only with a machine test (D398).
- Cycle 247 is read as `ORIGIN` only while the active chain holds nothing but datum shifts and, optionally, a tilt; the tilt (`PLANE` or cycle 19) is written again after `ORIGIN` with `MOVE=STAY`. While a mirror, a rotation or a scaling is active the block stays `RAW` with a WARNING, because the TNC 640 resets them and the iTNC 530 manual names only the datum shift (D253).
- `PLANE SPATIAL SPA+0 SPB+45 SPC+0 TURN MB MAX FMAX SEQ- TABLE ROT`: tilted working plane by spatial angles; `PLANE AXIAL A-90 C+180 STAY` by rotary axis positions (the dominant form in CAM output); `PLANE EULER`, `PLANE PROJECTED`, `PLANE VECTOR`, `PLANE POINTS`, `PLANE RELATIV` are the other forms; `PLANE RESET STAY` cancels. `TURN` positions the rotary axes without a compensating motion and takes `MB`, `MOVE` positions them while the tool tip stays on the workpiece (`ABST` distance), `STAY` only rotates the coordinate system. `MB` is a retract path, incremental from the current tool position in the active tool-axis direction, which the control travels before the swivel (`MB MAX` to just short of the software limit switch): the reader writes it as a `RETRACT` block in front of the `TILT`, as it writes the Siemens `_FR` (D228). `TABLE ROT`/`COORD ROT` decide whether a rotary table turns the workpiece or only the coordinates rotate; `SEQ+`/`SEQ-` selects the solution. The older `CYCL DEF 19.0 BEARBEITUNGSEBENE`, `19.1 A.. B.. C..` is the same tilt by axis angles, cancelled by `19.1` without axes.
- `M91` (above) is the machine frame per block.

## 4. Tools and spindle

- `TOOL CALL 4 Z S1592 F500 DL+0.1 DR-0.05`: tool 4 in the spindle, Z as the tool axis (which also sets the working plane), speed 1592, optionally the feed and delta offsets; the `F` of a `TOOL CALL` is the ordinary modal feed, which holds until a positioning block or another `TOOL CALL` programs a new one and which `F AUTO` takes (D251); the length and radius come from the tool table implicitly, which is why NCX readers emit both offset words with the number of the tool. `TOOL CALL S2000` without a number only changes the speed on the iTNC 530 and the TNC 640, whose keying procedure for a programmed speed change skips both the tool number and the spindle axis (D180); `TOOL CALL 0` empties the spindle. `TOOL DEF 5` prepares the next tool (preload). `TOOL CALL "NAME"` by name on the TNC 640 and on the iTNC 530 (606420); the row of the tool table maps the name to the number. NCX keeps such a call `RAW:HEIDENHAIN` with a WARNING in 1.0, because `OFFSET:LEN` and `OFFSET:RAD` take a register number (D239, to be revisited with D172).
- Measurement points (D373, D375): an index after the tool number, `TOOL CALL 5.1`, calls a further line of the tool table with its own length, radius and deltas, at most nine indices per tool (iTNC 530 Klartext 2010 p. 165-166, MP7262 p. 663; TNC 640 Setup 10/2019 p. 133, p. 137), so point k is index k-1 and a point above 10 is the ERROR CMP124 (D388). The call carries a tool number, so the TNC 640 runs its change macro (Klartext 892903-18 p. 123); on the iTNC 530 that depends on MP7480.0 and the builder's macro (Technisches Handbuch p. 1251, p. 1609-1614), hence the WARNING CMP123 for a point change of the tool in the spindle unless `point_change = "call"`. `DL`, `DR` and `DR2` are deltas added to the table and are never written for `TIP_OFFSET` and `POINT_RADIUS`, which the indexed line already holds.
- `M3`/`M4`/`M5` spindle, `M13`/`M14` spindle plus coolant, `M8`/`M9` coolant, `M6` tool change on older machines (usually inside the `TOOL CALL` macro), `M19` oriented stop is the builder's. A spindle table that names an `ORIENT` code without an angle reads as `ORIENT` at 0 with the WARNING RDR021, the angle being set by the machine (D154); a code several states of the machine write reads into every state the source does not rule out, the first one with RDR020 where two resources would be switched on (D155).
- Turning on the TNC 640 (`FUNCTION MODE TURN`, back with `FUNCTION MODE MILL`): X values are diameters, radial infeeds are radius values; `FUNCTION TURNDATA SPIN VCONST:ON S200` constant surface speed with `SMAX`; cycles 800 (adapt the coordinate system), 801, 810..8xx (turning contours, grooves, threads). Mill-turn programs of this kind exist in the corpus; Heidenhain turning is not part of version 1.0, the words are documented for the reader that comes later.

## 5. Cycles

Drilling cycles are defined with `CYCL DEF` and called separately:

```
CYCL DEF 200 BOHREN ~
    Q200=+2    ;SICHERHEITS-ABST. ~
    Q201=-21.732 ;TIEFE ~
    Q206=+565  ;VORSCHUB TIEFENZ. ~
    Q202=+21.732 ;ZUSTELL-TIEFE ~
    Q210=+0    ;VERWEILZEIT OBEN ~
    Q203=+0    ;KOOR. OBERFLAECHE ~
    Q204=+50   ;2. SICHERHEITS-ABST. ~
    Q211=+0    ;VERWEILZEIT UNTEN
L X+10 Y+10 R0 FMAX M99
CYCL CALL
```

- `Q200` safety clearance above the surface, `Q201` depth (incremental, negative), `Q202` infeed depth, `Q203` surface coordinate (absolute), `Q204` second clearance (the retract height after the cycle, acting only when it is programmed greater than `Q200`, D226), `Q206` plunge feed (`VORSCHUB TIEFENZ.`, the feed of cycle 206 among others), `Q210`/`Q211` dwells at the top and at the bottom, `Q207` milling feed (`VORSCHUB FRAESEN`, the milling cycles, 251 to 257 among them; never a tapping feed), `Q239` pitch (207, 209 and the thread-milling cycles), `Q256` retract for chip breaking (203; the lift the control holds, written from the machine key `[cycles] chip_break_lift`, never a catalog default, D358), `Q257` chip breaking depth, `Q208` retraction feed (D178). The NCX reader converts to absolute coordinates along the tool axis: `SURFACE = Q203`, `CLEARANCE = Q203 + Q200`, `DEPTH = Q203 + Q201`, `SAFE = Q203 + Q204`.
- `Q202` is the infeed counted from the surface `Q203`, to which the depth `Q201` is relative too (iTNC 530 Zyklen 670388-12, cycle 203, p. 87, 89-90), so the NCX `PECK`, an infeed from `SURFACE`, is `Q202` unchanged (D355). `Q256` takes 0.1 to 99999.9999 (p. 89-90).
- Cycles 200 (drilling), 201 (reaming), 202 (boring), 203 (universal drilling with chip breaking and decreasing pecks), 204 (back boring), 205 (universal pecking), 206/207 (tapping with and without a compensating chuck; 207 rigid), 208 (bore milling), 209 (tapping with chip breaking), 240 (centering), 241 (single-lip deep hole).
- The `Q` parameters of a cycle stand in the control's own order, the order of the NC example of the cycle manual, and that is the order a `CYCL DEF` is written in (D178): 200 = `Q200 Q201 Q206 Q202 Q210 Q203 Q204 Q211`; 201 = `Q200 Q201 Q206 Q211 Q208 Q203 Q204`; 202 = `Q200 Q201 Q206 Q211 Q208 Q203 Q204 Q214 Q336`; 203 = `Q200 Q201 Q206 Q202 Q210 Q203 Q204 Q212 Q213 Q205 Q211 Q208 Q256`; 204 = `Q200 Q249 Q250 Q251 Q252 Q253 Q254 Q255 Q203 Q204 Q214 Q336`; 205 = `Q200 Q201 Q206 Q202 Q203 Q204 Q212 Q205 Q258 Q259 Q257 Q256 Q211 Q379 Q253`; 206 = `Q200 Q201 Q206 Q211 Q203 Q204`; 207 = `Q200 Q201 Q239 Q203 Q204`; 208 = `Q200 Q201 Q206 Q334 Q203 Q204 Q335 Q342 Q351`; 209 = `Q200 Q201 Q239 Q203 Q204 Q257 Q256 Q336 Q403`; 240 = `Q200 Q343 Q201 Q344 Q206 Q211 Q203 Q204`; 241 = `Q200 Q201 Q206 Q211 Q203 Q204 Q379 Q253 Q208 Q426 Q427 Q428 Q429 Q430 Q435`; 251 = `Q215 Q218 Q219 Q220 Q368 Q224 Q367 Q207 Q351 Q201 Q202 Q369 Q206 Q338 Q200 Q203 Q204 Q370 Q366 Q385`; 252 = `Q215 Q223 Q368 Q207 Q351 Q201 Q202 Q369 Q206 Q338 Q200 Q203 Q204 Q370 Q366 Q385`; 253 = `Q215 Q218 Q219 Q368 Q374 Q367 Q207 Q351 Q201 Q202 Q369 Q206 Q338 Q200 Q203 Q204 Q366 Q385`; 254 = `Q215 Q219 Q368 Q375 Q367 Q216 Q217 Q376 Q248 Q378 Q377 Q207 Q351 Q201 Q202 Q369 Q206 Q338 Q200 Q203 Q204 Q366 Q385`; 256 = `Q218 Q424 Q219 Q425 Q220 Q368 Q224 Q367 Q207 Q351 Q201 Q202 Q206 Q200 Q203 Q204 Q370`; 257 = `Q223 Q222 Q368 Q207 Q351 Q201 Q202 Q206 Q200 Q203 Q204 Q370`.
- Cycle 200 is a plain drilling with `Q211`=0 and a drilling with a dwell at the bottom with any other `Q211`; cycle 203 retracts fully after every infeed with `Q213`=0 and never retracts with a `Q213` of at least the number of infeeds, `ceil(|Q201| / Q202)`, which are the two cycles NCX calls `PECK` and `CHIP_BREAK`; a `Q213` between the two is the mixed form, which NCX has no cycle for (D163).
- `CYCL CALL` calls at the current position; `M99` in a positioning block calls at that position; `CYCL CALL PAT` calls at every point of a `PATTERN DEF`; `CYCL CALL POS X Y Z` calls at a position, always with three coordinate axes, and its tool-axis coordinate acts as an additional datum shift on the whole cycle, which is why NCX keeps the block `RAW` (D189). The definition stays active until the next `CYCL DEF`; a positioning block between the definition and its first call does not end it. There is no cancel word, so the NCX reader emits `CYCLE=OFF` before the first non-cycle motion after a call of the cycle, and before a `TOOL CALL` while NCX has the cycle on; a call made while NCX has the cycle off writes the definition again (D227).
- The third coordinate of a `PATTERN DEF` point, `POS1 (X+25 Y+33.5 Z+0)`, is the workpiece surface the position starts at: a value other than 0 acts in addition to the `Q203` of the machining cycle, so the NCX reader writes the `CYCLE` block again before that point's call with `SURFACE`, `CLEARANCE`, `DEPTH` and `SAFE` shifted by it (D254).
- Pockets and studs: 251 (rectangular pocket), 252 (circular pocket), 253 (slot), 254 (circular slot), 256/257 (studs), 233 (face milling), 262..267 (thread milling); contour cycles: `CYCL DEF 14 KONTUR` names the label subprograms, 20 (contour data), 21 (pilot drilling), 22 (rough-out), 23 (floor finishing), 24 (side finishing), 25 (contour train), 270/271; `CYCL DEF 9.0 VERWEILZEIT`, `9.1 V.ZEIT 1.5` dwell; 12 (`PGM CALL`), 13 (spindle orientation).
- Probing cycles `TCH PROBE 4xx`, OEM cycles 3xx (Hermle), and the turning cycles 8xx are catalog entries or `RAW`.

## 6. Q parameters and FN functions

- `Q0`..`Q99` free, `Q100`..`Q199` reserved for the control's cycles (read by programs), `Q200`..`Q1199` cycle parameters, `Q1200`..`Q1399` reserved, `Q1400`..`Q1999` free again; `QL0`..`QL499` local to the program level, `QR` remanent (kept after power-off), `QS` strings.
- `FN 0: Q5 = +10` assign, `FN 1` add, `FN 2` subtract, `FN 3` multiply, `FN 4` divide, `FN 5` square root; the formula syntax `Q1 = Q2 + 3 * SIN Q3` with the functions `SIN COS TAN ASIN ACOS ATAN SQRT ABS INT FRAC SGN NEG LN LOG EXP` and `^` (power), `%` (modulo); `FN 9: IF +Q1 EQU +Q3 GOTO LBL 5` (equal), `FN 10: IF +10 NE -Q5 GOTO LBL 10` (unequal), `FN 11: IF +Q1 GT +10 GOTO LBL 5` (greater), `FN 12: IF +Q5 LT +0 GOTO LBL "ANYNAME"` (less), each with the sign on both values (D336); `FN 14` error message, `FN 16: F-PRINT` output to a file, `FN 18: SYSREAD` system data (positions, tool data, cycle results), `FN 19` PLC values, `FN 20: WAIT FOR` synchronization with the PLC, `FN 26`..`FN 28` table access, `FN 29` PLC output, `FN 37` export.
- `INT` cuts the decimals without rounding and `FRAC` cuts the digits before the point, so both truncate toward zero and `INT(x) + FRAC(x)` is `x`, which is what NCX `INT` and `FRAC` mean (D119).
- `FN 18: SYSREAD` selects its datum by a group number (ID), a number (NR) and, where needed, an index (IDX), and stands in a block of its own that assigns into a `Q` parameter, `FN 18: SYSREAD Q25 = ID210 NR4 IDX3`; the compiler assigns into the highest free `QL` of the D338 pool (D397). The ids a machine file maps to `SYS_` names (machine-config 7): `ID270 NR1 IDX<axis>` the position in the active coordinate system and `ID240 NR1 IDX<axis>` the nominal position in the REF system, with the axis index 1=X, 2=Y, 3=Z, 4=A, 5=B, 6=C, 7=U, 8=V, 9=W; `ID50 NR4 IDX<tool>` and `ID50 NR5 IDX<tool>` the length and radius oversizes DL and DR of the tool table, the active tool's without an index; `ID200 NR1` and `NR2` the active tool radius and length including the delta values (D182).
- Expressions may stand wherever a number stands (`L X+Q1 Y-Q2`); the reader keeps `Q` names as NCX variable names (`Q5`, `QL5`, `QR5`, `QS5`).

## 7. Reading Klartext

1. Every block carries its verb; the reader still needs the state for the modal feed, the compensation, the active cycle definition and the active `CC` pole. A subprogram starts from the facts every call agrees on, fact by fact; a block that depends on a fact the calls disagree on, or one no call has reached, stays `RAW` with its WARNING, and after the call the caller continues with what the subprogram may change unknown (D225).
2. `TOOL CALL n Z S` gives `TOOL=n RPM=` and both offset words with n; a changed axis letter gives `WORKPLANE`; `TOOL DEF n` gives `PRELOAD=n`; `TOOL CALL "NAME"` stays `RAW` with a WARNING (D239).
3. `LBL n` closed by `LBL 0` and called without `REP` is a subprogram (`SUB=BEGIN NAME=n` section of the file); an `LBL` used by `REP` or as an `FN 9`..`FN 12` target is a `LABEL`; `CALL LBL n REP k` is `REPEAT=n TIMES=k`; an `FN 9`..`FN 12` jump out of the part between `LBL n` and its `CALL LBL n REP k` has the WARNING RDR303, because the control may keep the remaining `REP` count while NCX ends the repeat (D213). `CALL PGM` gives `CALL="name"` with the path and a `.h` or `.H` dropped; any other extension, the `.I` of a DIN/ISO program, keeps the block `RAW` with a WARNING (D215). The `FN 9: IF +0 EQU +0 GOTO LBL m` to an `LBL m` directly before a section's `LBL 0`, which the compiler writes for a `RETURN` before the end (D272), reads back as a `JUMP` plus a `LABEL`, not as `RETURN`; both mean the same. A subprogram section the main flow also runs through, one before the `M2` or `M30` or in a program without one, is written as a `SUB` section behind the program with a `CALL=n` where it stood, which runs the same blocks in the same order (D254; language 4.13, D89).
4. `M30` and `END PGM` together are `PROGRAM=END`; a missing `M30` is a WARNING; sections after `M30` that are jumped into are moved in front of the end behind `JUMP=END`.
5. `CC` and `C` become one `ARC` block with an absolute `CENTER`; `CR` becomes an `ARC` with `R`; `CP IPA` beyond 360 degrees becomes `ARC` with `ANGLE`; `LP`/`CP`/`PA`/`PR` are converted to Cartesian with the pole. A number the reader computes (a polar point, a tangential arc centre, a chamfer or rounding point) keeps six decimals, half away from zero, trailing zeros dropped (D403, the D121 precision of the virtual machine). A `CC` with exactly one axis of the plane leaves the pole unknown: the arcs about it stay `RAW` with a WARNING that names the `CC` (D400). A `CHF` next to an arc stays `RAW` with the reason "CHF only between two straight lines" (D401); a `CHF` or `RND` before a `CT` stays `RAW`, and the `CT` with it, with a WARNING naming the `CT` (D402).
6. `CYCL DEF 7` replaces the previous shift (`SHIFT=RESET` before the new `SHIFT`); `PLANE SPATIAL` is `TILT`, `PLANE AXIAL` and cycle 19 are `TILT_AXIS`, with `MOVE` and `ROT` from the options and the `MB` of a `TURN` as a `RETRACT` block in front of the tilt (D228); a `PLANE SPATIAL` that names neither `TABLE ROT` nor `COORD ROT` is read as `ROT=COORD`, the default of the TNC 640 ("Wenn keine Transformationsart gewählt wurde, verwendet die Steuerung für die PLANE-Funktionen die Transformationsart COORD ROT", TNC 640 Klartext 892903-18 p. 436), assumed for the iTNC 530 by family continuity, since NCX itself defaults to `TABLE` (D269); a replacing cycle 7, 8, 10 or 19 or absolute `PLANE` and cycle 247 as section 3 says (D253); other `PLANE` forms are `RAW`, and so is a `PLANE RESET` with `TURN` or `MOVE`, which positions the swivel axes back into their basic position and has no NCX form in 1.0 (D228).
7. Cycle definitions become `CYCLE=` blocks with absolute coordinates; `CYCL CALL`, `M99` and `CYCL CALL PAT` become `CYCLE_CALL` blocks (a pattern expands to one call per point, with the `CYCLE` block written again where the surface of a point shifts it, D254), each with the axis words its source block carries, so a bare `CYCL CALL` becomes a bare `CYCLE_CALL` (D220). Cycle 200 with `Q211`=0 is `DRILL` and with any other `Q211` is `DRILL_DWELL` with `CYCLE_DWELL`=`Q211`; cycle 203 with `Q213`=0 is `PECK` and with a `Q213` of at least `ceil(|Q201| / Q202)` is `CHIP_BREAK`, any `Q213` between the two being read natively as `CYCLE:HEIDENHAIN=203` (D163). A `Q204` from 0 up to `Q200` reads as `CYCLE_RETRACT=CLEARANCE` without `SAFE`, a `Q204` greater than `Q200` as `SAFE` = `Q203 + Q204` with `CYCLE_RETRACT=SAFE` (D226). A definition whose `Q` parameters that no NCX word carries hold the values the compiler would write (the `defaults` of the catalog entry, D164: `Q210`=0, `Q212`=0, `Q208`=`MAX` on 203, and the block rules of 8 rule 7) is read as the named entry; the reader does not compare a value the cycle does not use in that form (`Q256` when `Q213`=0, `Q205` when `Q212`=0), asks `[cycles] chip_break_lift` before the catalog for `Q256` (D358), and keeps any other definition as `CYCLE:HEIDENHAIN=n` (D94, D5).
8. The comma is the decimal separator; the reader accepts both.
9. `BLK FORM`, `APPR`/`DEP`, `TCH PROBE`, `FN 16`/`FN 18`/`FN 19`, `PATTERN DEF` beyond the expanded calls, and OEM cycles are `RAW` with a WARNING. The blank stays `RAW` although a `STOCK` word exists, because the control's forms carry shapes and arguments the word does not (D352).
10. The word of an `M` function that acts at the end of a positioning block stands in a block of its own directly after the motion; the others stand in the block of the motion, whose state words act before it (section 2; language 5 rule 3; D252).

## 8. Writing Klartext

1. Consecutive block numbers from 0 in steps of 1, the Heidenhain family value of `[format] block_numbers` when the machine file leaves it out (machine-config 2, D263), `BEGIN PGM name MM` from the program name and the units, `END PGM name MM` after `M30`. A name with a character outside A-Z a-z 0-9 _ -, or longer than 25 characters on the iTNC 530, is written with the WARNING CMP127 (D266).
2. Comma as the decimal separator, sign on every coordinate, `FMAX` for `RAPID`, `F` on `LINE` blocks when the feed changed; `F` is modal on the control, so no machine setting writes it on every block (D273); `R0`, `RL` or `RR` on the `L` block only, where the compensation changed, so a motion Klartext writes without an `L` block that would run with another one is an ERROR (D345). A formula where a number stands, in a motion word or an operand of `FN 9`..`FN 12`, is set in a `QL` parameter in a block of its own directly before the block, `QL499 = Q1 + 5`, then `L X+QL499`: the compiler takes the highest `QL` numbers (of `QL0`..`QL499`) that no word of the file names and that `[format] counter_registers` does not hold, and the ERROR CMP102 remains only where no `QL` is free. A jump that compares two strings, `==` or `!=` of two `QS` parameters, is `QLn = STRCOMP ( SRC_QS1 SEA_QS2 )` and `FN 9: IF +QLn EQU +0` or `FN 10: IF +QLn NE +0` (STRCOMP gives 0 for identical strings, iTNC 530 DIN/ISO 606420-01 p. 291); any other comparison with a string is the ERROR CMP126 (D169) (D338; the `SETPOS` values D338 also names are not spilled yet and stay CMP102). The same holds for `F` and `S`: a formula or a parameter with a sign there is spilled into the highest free `QL` in a block of its own directly before the block, which writes `FQL499` or `SQL499` (D396). A `SYS_` name of `[system_variables]` is read by `FN 18: SYSREAD QLn = ID.. NR.. IDX..` into the highest free `QL` of the same pool, in a block of its own directly before the block that uses it, one `QL` per distinct name in the block; CMP102 where no `QL` is free (D397).
3. `TOOL CALL n axis S` assembled from `TOOL`, `WORKPLANE` and the `RPM` of the same or the following block, which is the first block after the `TOOL` block, in its section, that holds more than `PRELOAD` words (a `TOOL DEF` has no speed field, so a preload is never the block the speed comes from); what the call folds in is not written again (D275). An `F` of the `TOOL` block is folded into the call, where it is the modal feed of the control (D251). A `WORKPLANE` that changes the tool axis of the last `TOOL CALL` needs a `TOOL` in its own block, or must stand in that following block: Klartext fixes the working plane at the tool call with the spindle axis, and no other block sets it, so every other form is an ERROR (D321). A speed change without a tool is written as the machine's `RPM` template and never repeats the tool number: a `TOOL CALL` that carries a tool number, a tool name or a changed tool-axis direction runs the machine's tool-change macro and may swap in a sister tool, while a `TOOL CALL` with neither name nor number, and either no tool axis or the previous one, changes only the speed (D180). `TOOL DEF n` for `PRELOAD`.
4. Arcs in the plane as `CC` plus `C` (the canonical form) or `CR` when the NCX block had `R`; helices and sweeps beyond a turn as `CP IPA`, with the travel along the tool axis as the incremental `IZ` and, for an `R` form, the centre the virtual machine computed (D268). D365: the compiler computes the end `CP IPA` reaches from the written start, pole and angle and reports the WARNING CMP031 where it lies farther from the rounded end point than `ROUND_LIMIT`, or half an output step without it; the decimals of `ANGLE` are the one lever.
5. `HOME` as `L ... FMAX M91` to the reference coordinates (`home`, or `home2` for `POINT=2`) of the `[[axis]]` table (there is no reference return command); an axis without them is an ERROR of this compiler, not of `ncx check` (D100). A `SETPOS` of an axis whose position is known in the `MACHINE` frame only, after `HOME` or a machine-frame move, is the ERROR CMP113: no cycle 7 or `TRANS DATUM` takes a machine-frame position, and `FN 25` is locked on the iTNC 530 and absent on the TNC 640; D397 settles the target of the `FN 18` read, which unblocks the ID270/ID240 route; until that route is built the case stays CMP113 (D320). A `CYLINDER` section (`CYLINDER=r` .. `CYLINDER=OFF`) is `CYCL DEF 14.0 KONTUR`, `CYCL DEF 14.1 KONTURLABEL n`, `CYCL DEF 27 ZYLINDER-MANTEL` and `CYCL CALL` only where it has the shape the cycle executes itself: positioning `RAPID`s above the start point, one `LINE` along the radial axis to a constant depth (the plunge), a chain of `LINE` and `ARC` in the cylinder plane at that depth under `COMP=LEFT` or `RIGHT` with one feed, and a retract along the radial axis back to the radius the plunge started from; several passes with the same contour at increasing depth set the infeed. `Q1` = depth − r, `Q3` = 0, `Q6` = plunge start − r (greater than the tool radius, else CMP101; the WARNING CMP131 where the tool table gives no radius), `Q10` the infeed, `Q11` and `Q12` the feeds of the plunge and the contour, `Q16` = r, `Q17` = 1 (the C word is a length, D102). The contour is a subprogram `LBL n` .. `LBL 0` after the `M30`, with the label of the D271 numbering, both coordinates and `RL`/`RR` in its first block, `L`, `CR` and `CC` plus `C`: on the TNC 640 X along the circumference and Y along the axis, on the iTNC 530 the machine's rotary letter and the letter of the parallel axis (D146); `DR` follows the order of those two letters in the plane. Any other section is CMP101 and writes nothing (D394).
6. Subprograms as `LBL n` ... `LBL 0` after the `M30` of every program that calls them; the option of separate `.h` files with `CALL PGM` is struck for 1.0 (D274). A subprogram that no program calls stands once in the first program's file, after its subprograms and before its `END PGM` (D264). `BEGIN PGM` and `END PGM` carry the file's final name: a name taken already, compared case-insensitively, gets `_2`, `_3` with the WARNING CMP005 (D266). Kept for later: a `CALL PGM` file ends with `END PGM` and holds no `M2`/`M30`, is named by its path relative to the caller, and `Q` parameters are global across the call. The labels of each Klartext program are numbered within `[format] label_max`: a numeric `LABEL` or `SUB` name that is unique, not 0 and within the range keeps its number, every other one (a later duplicate, 0, an identifier, a string, a number out of range) gets the lowest free number in block order, and a range without a free number is the ERROR CMP129; `LBL "NAME"` is never written, and `LBL 0` only as the end of a subprogram (D271). The subprograms are numbered once for the compile, since their text stands in every caller's file. A `RETURN` before the end of a subprogram is `FN 9: IF +0 EQU +0 GOTO LBL m`, under `IF` `FN 9`..`FN 12` with the condition, to an `LBL m` directly before the section's one `LBL 0`; a `RETURN` directly before `SUB=END` writes nothing (D272). `REPEAT=n TIMES=k` is `CALL LBL n REP k`, and a `REPEAT` without `TIMES` is `CALL LBL n REP 1`, since a `CALL LBL` without `REP` is a subprogram call (D399); where a `JUMP`, `JUMP=END` or `RETURN` leaves the part between the label and the `REPEAT`, it is a counter loop instead, because the control keeps the `REP` count as block state that only `GOTO 0` or a new program selection resets: `QLc = 0` before `LBL n`, then `QLc = QLc + 1`, `FN 12: IF +QLc LT +k+1 GOTO LBL n`, `QLc = 0` at the `REPEAT`, with `QLc` from `[format] counter_registers`; a machine without the key is the ERROR CMP130 (D213, D388 (12)). The `ARG` values of a `CALL` are `Q` parameters set before the call, which survive it on the control, while NCX makes each `ARG` name a local of the call: a caller that reads such a name after the call, before assigning it, is the ERROR CMP125 (D149).
7. Cycle blocks as `CYCL DEF` with the `Q` parameters in the control's order (section 5) and `CYCL CALL` or `M99` for the calls; `CYCLE_RETRACT=SAFE` becomes `Q204`, and `CYCLE_RETRACT=CLEARANCE` becomes a `Q204` equal to `Q200`, which also ends the tool at the set-up clearance (D226). `Q211` is `CYCLE_DWELL`, or 0 where the block has none; `Q213` is 0 for `PECK` and the number of infeeds, `ceil(|Q201| / Q202)`, for `CHIP_BREAK` (D163). `CYCLE_RETRACT=SAFE` with a `SAFE` at or below `CLEARANCE` is the WARNING CMP140, since the control then retracts only to `Q200` (D157); `CYCLE_RETRACT=SAFE` without `SAFE` is the ERROR CMP104 (D188). The positions no word carries follow three block rules, as BOHREN.h writes them: `Q202` of 200 is the full depth, `Q205` of 203 equals `Q202`, and `Q208` of 201 equals `Q206`; `Q256` comes from `[cycles] chip_break_lift`, a value outside 0.1 to 99999.9999 being written as the nearest one with the WARNING CMP121 (D358); every other position takes the `defaults` of the catalog entry (D164). A cycle word the entry maps to no `Q` parameter is the WARNING CMP105 where the cycle reaches the value from another word (the feed of 207 from the pitch), is dropped silently where the value is what the control does anyway (`CYCLE_DWELL=0`, `PECK=0`), and is the ERROR CMP122 where it would be lost (D362). The head is `CYCL DEF n` with the `title` of the catalog entry, or the number alone without one (D270); for cycles above 200 every continued line ends with a tilde and the last parameter has none, and for cycles below 200 no cycle text ends with a dot (D270).
8. A word whose `M` function acts at the end of a positioning block, `SPINDLE=OFF` and `COOLANT=OFF`, is written in a block before the `L`, so that it acts before the motion as its NCX block says (section 2; language 5 rule 3; D252). `STOP` is written after the motion, not before the `L`: it is a block word and not a state word, and its NCX block stops when the motion of the block is done (language 4.1; virtual machine 3 steps 5 and 7), so an `M0` before the `L` would stop earlier than the NCX block says. D395 withdraws the half of D252's compiler sentence that named `STOP` with the two state words: D252's own evidence lists `M0` and `M1` among the functions that act at the block end.
9. `TILT` as `PLANE SPATIAL` through `[transform] TILT_ON`, always with the transformation type: `{rot}` takes `TABLE ROT` or `COORD ROT` from `[transform] rot`, an absent `ROT` as `TABLE ROT`, since NCX defaults to `TABLE` and the control to `COORD ROT` (D191, D269). A `ROT` on a `TILT_AXIS` block (`PLANE AXIAL`), and on a machine without any rotary axis, where no tilt frees one, has no effect: an INFO (CMP128), not written. A machine without the map, or a `TILT_ON` without `{rot}`, ignores a `ROT` the block states with the WARNING CMP108 of language 4.2.
10. A tool whose program names its measurement point (`TOOL_POINT` in its `TOOL` block or after it) is called with the index of the `[tool_points]` mapping, `TOOL CALL 5.1` for point 2 and the plain number for point 1 (section 4, D373, D393); a point change of the tool in the spindle is an indexed `TOOL CALL` with the axis and the speed and the WARNING CMP123 unless `point_change = "call"`, and a point above 10 is the ERROR CMP124 (D388). `TIP_OFFSET` and `POINT_RADIUS` are never written, no `DL`, `DR` or `DR2`; `point_comment = true` writes one comment line with the point, a and r; a program without point words compiles byte for byte as before (D375).

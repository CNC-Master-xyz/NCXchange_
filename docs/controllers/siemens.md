# SINUMERIK 840D and 840D sl

The Siemens language is DIN 66025 G-code extended by a high-level language: addresses with an equals sign, identifiers, typed variables, frames as first-class objects, subprograms with parameters, structured control flow, and cycles that are ordinary subprogram calls with positional parameters. The 840D (powerline, 1990s to 2010) and the 840D sl (solution line, 2005 on, software 2.x to 4.9x) share the language; the sl added the trailing mode parameters on the cycles, `CYCLE800`, `CYCLE832` and the ShopMill/ShopTurn cycle set. SINUMERIK ONE (2019 on) keeps the language. Version 1.0 of NCXchange reads and writes generic 840D sl programs; the GILDEMEISTER structure programming of DMG lathes (`L7xx` cycles, `TC(...)`) is documented in `machine-builders.md` and not implemented (decision D68).

## 1. Program units and files

```
%_N_SHAFT_MPF
;$PATH=/_N_WKS_DIR/_N_SHAFT_WPD
N10 G0 G40 G90 G94
N20 CYCLE800()
N30 G54
N40 T="SF8-ST-NL30-SL21" D1
N50 M6
...
N600 M30
```

- A unit is a main program (`MPF`) or a subprogram (`SPF`); in a file exported from the control it starts with `%_N_NAME_MPF` and a `;$PATH=` comment that names the workpiece directory; on the control itself the header is not part of the text. A job archive holds several units in one file (`%_N_1_0_MPF`, `%_N_TH1_HS_01_SPF`, a tool list `%_N_1_3_MPF`, an `_INI` unit), one after another: the NCX file structure with several programs and subprograms per file exists for this.
- Program names: letters, digits, underscore, up to 24 characters; the first two characters should be letters or an underscore and a letter, because a name that starts with a digit can only be called through `CALL`. Names are case-insensitive, except tool names in `T="..."`.
- Blocks end with the line feed, `N` numbers optional (they must be unique for the block search), at most 512 characters per block, which are the Siemens family values of `[format] line_ending` and `max_line_length` when the machine file leaves them out (machine-config 2, D263); `;` starts a comment at the end of a block or a comment block; `/` or `/0` skips the block on the first skip level, `/1`..`/9` on the others.
- The recommended order in a block is `N G X Y Z F S T D M H`, but the control does not require it; some addresses may appear several times (`G`, `M`, `H`).
- Ends: `M30` (rewind), `M2`, `M17` (subprogram return, also accepted in a main program, where it acts as `M2`/`M30`; an `M2`/`M30` in a subprogram acts as `M17` and returns to the caller, since the NC language treats `M17` and `M30` as equal, D344), `RET` (return without an output to the PLC, in a subprogram only; its parameterized form `RET("<target>", <block after the target>, <levels>)` continues at that block number, label or string in the program the given number of levels up, 1 to 15, and `$P_STACK` is the current program level, so `RET("<label>",,$P_STACK)` returns to level 0 from any depth (D344): in the main program level it is alarm 14091, so NCX keeps it `RAW` there and `PROGRAM=END` is written `M30`, `M2` or `M17`, never `RET`; D346). `M0`, `M1` (written `M01` by some posts) stop.
- Values: `X10` for a single-letter address with a constant; `X=10` when the value is an expression or a variable (`X=R1*2`, `Z=R40`); the `=` is required after every multi-letter address and after an address with a numeric extension (`CR=5`, `AR=90`, `S2=1000`, `X1=10`, `M2=3`). Separators after the address are allowed (`F 100`).
- Address extensions select an object: `S2=` spindle 2, `M2=3` spindle 2 clockwise, `T2=` tool selection for spindle 2, `X1=` machine axis X1 in `G74`, `C4=` a fourth C axis (the corpus drives spindle 4 as a C axis this way), `I1=` the intermediate point of `CIP`.

## 3. Motion

- `G0` rapid (linear interpolation or per axis by machine data, `RTLION`/`RTLIOF`), `G1` at `F`, `G2`/`G3` arcs.
- Absolute or incremental: `G90`/`G91` modal, `X=AC(10)` and `X=IC(5)` per word; rotary axes `C=DC(90)` shortest way (also for `SPOS`), `C=ACP(90)` positive direction, `C=ACN(90)` negative direction; `G91` with `IC` may turn a modulo axis by more than 360 degrees.
- Arcs: end point with `I J K` (center incremental from the start point; `I=AC(50)` absolute; the corpus writes `I=AC() J=AC()` throughout; a center parameter whose value is 0 may be left out, while the belonging second one of the plane must be given in every case, so an arc that writes neither center word of its plane and no `CR` or `AR` is no arc and stays `RAW`; D340), `CR=5` radius (negative for the arc over 180 degrees; a full circle needs the center), `AR=90` opening angle with the end point or the center, `CIP X Y I1= J1=` through an intermediate point, `CT X Y` tangential; `TURN=2` on a helix adds two full turns before the end point; arcs outside the working plane are possible when the end point names the axes. `INVCW`/`INVCCW` involutes.
- Polar: `G110`/`G111`/`G112` define the pole (relative to the last position, the workpiece zero, the last pole), then `G0`/`G1`/`G2`/`G3 AP=30 RP=50`; switching back to Cartesian happens by writing Cartesian words. The pole stays until the program end.
- Chamfer and rounding: `CHF=2` (chamfer length), `CHR=2` (chamfer width in the original direction), `RND=4` (radius), `RNDM=4` modal rounding (`RNDM=0` off), with `FRC=` (blockwise) or `FRCM=` (modal) feeds; contour definitions with `ANG=` (a line by angle) and two- or three-block forms that the control completes.
- Feed: `F` (one per block), `G94` per minute, `G95` per revolution of the master spindle, `G93` inverse time, `G95 FZ=` per tooth, `FGROUP(X, Y, Z, A)` names the path axes the feed refers to and `FGREF[A]=r` the effective radius of a rotary axis, `FL[Y]=500` a velocity limit, `FB=` blockwise feed, `OVR=` override, `ACC[X]=` acceleration limit, `FA[X]=` feed of a positioning axis.
- Path control (the reader writes `G60` as `PATH_MODE=EXACT_STOP` and `G64` as `PATH_MODE=CONTINUOUS`, and keeps the other words of this list `RAW`, D349): `G60` exact stop (with `G601`/`G602`/`G603` criteria), `G9` blockwise, `G64` continuous, `G641 ADIS=0.5 ADISPOS=2` smoothing by distance, `G642` by axis tolerance, `G643` inside the block, `G644` by dynamics, `G645` also at tangential transitions; `CTOL=`, `OTOL=`, `ATOL[X]=` contour, orientation and axis tolerances; `COMPON`/`COMPCURV`/`COMPCAD`/`COMPSURF` compressors; `CYCLE832(tol, mode, otol)` sets all of this for HSC programs (mode 1 finish, 2 semi-finish, 3 rough, 4 precision, plus 10 for an orientation tolerance in the third parameter; `CYCLE832(0, 0, 1)` off). Under SINUMERIK Operate the third parameter is mandatory and is 1 for a program without tool orientation (`CYCLE832(0.004,_FINISH,1)`); up to SW 7.5 the cycle took two parameters, so the form is a template of the machine file: `ON` without and `ON_ROTARY` with the orientation tolerance, `CYCLE832({tol},{mode},1)` and `CYCLE832({tol},1{mode},{rotary})` in the shipped 840D sl files (D151; 840D sl/828D Arbeitsvorbereitung 2013 p.714-716, NC-Programmierung SW 4.92 p.1126-1127).
- Radius compensation: `G41`/`G42`/`G40` with `D`; `NORM` (straight approach), `KONT` (around the corner), `KONTC`/`KONTT` (continuous); `G450` (transition circle at outer corners, `DISC=`) or `G451` (intersection); `OFFN=` contour allowance; `CUT2D`.. `CUT3DC` offset types; `G147`/`G148`/`G247`/`G248`/`G347`/`G348` smooth approach and retreat (`RAW`).
- Machine frame: `G53` (one block, programmable and settable frames off), `G153` (also the base frame), `SUPA` (also handwheel and external shifts, `PRESET`); the posts write `G0 G53 Z360 D0` (retract with the tool offset cancelled in the same block) and `G0 SUPA Z1800 D0`.
- `G74 X1=0 Y1=0 Z1=0`: reference point approach with machine axis names, own block, no transformation active; `G75 X0 Z0 FP=2`: fixed point 1..4 of MD30600, a missing `FP` or `FP=0` being `FP=1` (Programmierhandbuch Grundlagen 2013 p.377-378). `G74` is `HOME` without `POINT`, the counterpart of Fanuc `G28`; `G75 FP=2..4` is `HOME POINT=2..4`, the counterpart of Fanuc `G30 P2..P4`; `G75 FP=1` and `G75` without `FP` stay `RAW:SIEMENS` with the WARNING RDR509, since `POINT=1` is the reference point `G74` approaches (D260).
- `G4 F1.5` dwell in seconds, `G4 S10` in revolutions of the master spindle, `G4 S2=10` of spindle 2; the `F` and `S` of a dwell block do not touch the modal feed and speed.
- `PRESETON(C, 0)` declares the current position of an axis (loses the reference status), `PRESETONS` keeps it.
- `WORKPIECE(, "", , "CYLINDER", 0, 1, -108, 0, 53.5)`: blank definition for the simulation (name, clamping, datum, shape `CYLINDER`/`PIPE`/`RECTANGLE`/`BOX`/`N_CORNER`, then the dimensions), header information only. The reader keeps it `RAW` in release 1 although the `STOCK` word exists, which the compiler writes through the `[stock]` template (D351, D352).

## 4. Frames

Under `DIAMON` a frame offset of the facing axis is a radius on the control (MD20360 bit 3 off, Funktionshandbuch Grundfunktionen 2012 p.901-903): on an X axis whose `programming` is diameter or switchable the reader doubles the X of `TRANS`, `ATRANS`, `G58` and `G59` into the NCX diameter, and takes it as written where `[[axis]] frames_in_diameter = true` (D125, D388). A `CYCLE800` with a non-zero `_X0` or `_X1` stays `RAW` there, since whether the cycle takes them as radii depends on MD20360 bit 14 (D125, D333).

- Settable: `G54`..`G57`, `G505`..`G599`, `G500` off (or `G500` with a value). The settable frame and the programmable frame are separate components of the total frame, so selecting a datum, and `G500`, leave the programmable frame standing; only a bare `TRANS`, `ROT`, `SCALE` or `MIRROR` clears it, and `G53`/`G153`/`SUPA` suppress it for one block. The reader therefore writes the entries of the programmable frame again after the `ORIGIN` that empties the chain (D340). A tilt of `CYCLE800` is no instruction of group 3 and is not written again: whether a datum leaves the swivel standing is open (D333).
- The datum table is written from the program through `$P_UIFR[n, X, TR]=` (translation), `[.., FI]` (fine), `[.., RT]` (rotation) as the Burkhardt+Weber posts do.
- Programmable, modal, group 3: `TRANS X Y Z` absolute shift (replacing), `ATRANS X Y Z` additive; `ROT X.. Y.. Z..` rotation about the geometry axes (Euler order), `ROT RPL=30` about the normal of the plane, `AROT` additive; `ROTS`/`AROTS`/`CROTS` rotations by two spatial angles; `SCALE`/`ASCALE`; `MIRROR X0`/`AMIRROR X0` (the value is meaningless); `G58 X..`/`G59 X..` replace the absolute or the additive translation part per axis. Every replacing instruction (`TRANS`, `ROT`, `SCALE`, `MIRROR`, with or without values) deletes all earlier programmable frame instructions; the additive ones build on the current frame. `TRANS` alone (and `ROT`, `SCALE`, `MIRROR` alone) clears the programmable frame.
- `TOFRAME`/`TOROT`/`PAROT` and their `OF` forms align the coordinate system with the tool or the workpiece after a swivel; `CYCLE800` (below) is what the posts write.
- Frame variables: `$P_PFRAME`, `$P_UIFR[n]`, `$P_BFRAME`, `$P_ACTFRAME`; frame arithmetic (`CTRANS(X, 10)`, `CROT`, `CMIRROR`, `CSCALE`, `CFINE`) and `MEAFRAME` are `RAW`.

`CYCLE800(_FR, _TC, _ST, _MODE, _X0, _Y0, _Z0, _A, _B, _C, _X1, _Y1, _Z1, _DIR, _FR_I, _DMODE)` swivels the plane on a machine whose kinematics is set up under a name (`_TC`, `"HERMLE"`, `"DMG"`, `"TC1"`; `""` when there is one, `"0"` deselects): `_FR` retract before swivelling (0 none, 1 machine Z, 2 Z then XY, 4 in tool direction to the limit, 5 by `_FR_I`); `_ST` ones digit 0 new or 1 additive, tens digit 1 tracks the tool tip (`TRAORI`), hundreds digit aligns the tool instead of the plane; `_MODE` is bit coded: bits 7 and 6 select axis-wise angles (00), spatial angles (01), projection angles (10) or rotary axes direct (11); in the axis-wise mode bits 1 and 0 name the axis of the first rotation, bits 3 and 2 that of the second and bits 5 and 4 that of the third (01 = X, 10 = Y, 11 = Z: 27 = Z Y X, 39 and 57 in the corpus), each rotation builds on the one before it, and `_A`, `_B`, `_C` are the first, second and third rotation of that order, not the angles about X, Y and Z; with spatial angles the control turns by `_A` about Z and then by `_B` about the rotated Y, and bits 5 to 0 have no meaning (D335); `_X0 _Y0 _Z0` the reference point before and `_X1 _Y1 _Z1` after the rotation; `_A _B _C` the angles, which in the rotary-axes mode are the positions of rotary axis 1 and rotary axis 2 of the swivel data record `_TC` names (which machine axes those are belongs to the commissioned kinematics and never appears in the program, so the reader takes their NCX names from the `[transform] TILT_AXIS_ON` template of the machine, D296; the third field is then the rotation in the plane about the tool orientation, referred to the abscissa, and the direction selection is not offered); `_DIR` -1 or +1 positions the rotary axes (the smaller or larger solution), 0 only computes the frame; `CYCLE800()` cancels. A `TRAORI` after a plain `G0 A.. C..` positioning (Hermle) is a rotary motion followed by the transformation, not a swivel.

## 5. Tools and spindles

- `T1`, `T=1`, `T="DRILL_D8"` select a tool (by number, or by name and duplo under tool management; a locked tool is replaced by the search strategy); on turret lathes the selection is the change (manual 2.4.1); on mills `M6` performs the change (2.4.2), so `T1` before it is a preload; `T2=5` selects for spindle 2 where the machine allows the extension; `T0 M6` unloads; `T0` alone unloads on a turret, while on a mill it is `PRELOAD=0`, and `TOOL=0` only where the main program ends after it (`M30`, `M2`, `M17`) with no `M6` or other `T` in between; a `RET` is not an end (D297). A change `T5 M6` consumes any preload, also the `T3` of an earlier line, since the control's `T5` overwrites that selection; an `M6` alone after it changes to `T5` again, `TOOL=5`, and writes no `TOOL` where the reader knows no tool (D132). `D1`..`D8` select the cutting edge of the active tool with its length and radius (one register, NCX `OFFSET=`); `D0` cancels the offsets of the active tool, the length and the radius together (written in the retract blocks, and for a block that sets `OFFSET:LEN=0`, D301); `TOFFL`/`TOFF`/`TOFFR`/`TOFFLR` programmable offsets; `TCARR=`, `TCOABS`, `TCOFR` for orientable tool carriers.
- Measurement points (D373, D375): a bare `D` switches the offset data set of the active tool (`N50 T4 D2`, then `N70 G0 Z... D1`, Grundlagen 03/2013 p. 74), and an edge holds its own lengths, radius and wear (`$TC_DP1`..`$TC_DP25`, Funktionshandbuch W1 07/2012 p. 1596), so point k is `D k`, or the edge of a `[[tool_point]]` row where the edges are numbered freely (MD18105) or flat (MD18102 = 1, `edge_numbering = "flat"`). `TOFFL`, `TOFF`, `TOFFR` and `DL` are never written for `TIP_OFFSET` and `POINT_RADIUS`: they add to the edge, survive a change of tool or edge and are cleared at program end (Grundlagen p. 76-78).
- Spindles: `S1000` and `M3`/`M4`/`M5` for the master spindle, `S2=1000` and `M2=3` for spindle 2 (at most three `S` per block; `S0=` is the master spindle); `SETMS(2)` in its own block makes spindle 2 the master spindle that `S`, `M3`, `G95`, `G96` and `G4 S` refer to, `SETMS` alone returns to the configured one; `M70`/`M2=70` switches a spindle to axis mode, `SPOS=90`/`SPOS[2]=90` positions (`SPOSA` without waiting, `WAITS(1,2)` waits), `M19`, `SPOS=DC(45)` with a direction; `G96 S200` constant surface speed (switches `G95` on), `G961` with feed per minute, `G962` either, `G97` off with the feed type `G95` (it may be programmed without a preceding `G96` and then acts as `G95`), `G971` off with `G94`, `G972` off keeping the feed type before it, `G973` off without the speed limit and so with the feed per revolution, which has no NCX word and stays `RAW` (D342); `LIMS=3000` (and `LIMS[2]=`) the speed limit under `G96`; `G26 S1400 S2=350` upper and `G25 S20` lower limits for all spindles, kept beyond the program end; `SVC=` cutting speed for milling tools; `SCC[Y]` another reference axis for `G96`.
- Synchronous spindles: `COUPDEF(S2, S1, 1, 1, "NOC", "DV")` defines a coupling, `COUPON(S2, S1, 113.5)` switches it on with an angular offset, `COUPONC` keeps the current offset, `COUPOF` off, `COUPDEL` deletes; the DMG cycles wrap them.
- Coolant, chucks, clamps and everything else are the builder's M functions (`M8`/`M9` almost everywhere, `M108`/`M109` for the driven tools on the Monforts and the CLX, `M40`/`M41`/`M42` gear ranges).

## 6. Transformations and orientation

- `TRAORI` or `TRAORI(1)` switches the 5-axis transformation on (positions refer to the tool tip, rotary axis moves are compensated), `TRAORI(1, x, y, z, a, b)` with a tool direction and rotary offsets; `TRAFOOF` off; `TRACYL(d)` cylinder surface transformation (with `TRACYL(d, n)` and the groove-wall variant), `TRANSMIT` (`TRANSMIT(n)`) face transformation, `TRACON` chained transformations, `TRAANG` inclined axis, `TRAFOON` with kinematic chains (SINUMERIK ONE).
- Orientation under `TRAORI`: rotary axis positions `A B C`; Euler or RPY angles `A2= B2= C2=` (`ORIEULER`, `ORIRPY`, `ORIRPY2` select the convention); direction vector `A3= B3= C3=` (the tool axis in workpiece coordinates); surface normals `A4= B4= C4=` at the block start and `A5= B5= C5=` at the end; `LEAD=` and `TILT=` angles relative to the path (`ORIPATH`); `ORIAXES` (linear interpolation of the axes) or `ORIVECT` (great circle interpolation of the vector); `ORIWKS` (the vector is meant in the workpiece system, the default) or `ORIMKS` (in the machine system); `ORISON`/`ORISOF` smoothing; `ORIRESET(a, b)` basic position.
- `CUT3DC`/`CUT3DF`/`CUT3DFF` 3D radius compensation, `ORIC`/`ORID` behaviour at outer corners.

## 7. Cycles

A cycle is a subprogram call with positional parameters; empty positions take defaults. The 840D sl set (manual chapter 3.25), with the trailing `_GMODE`, `_DMODE`, `_AMODE` integers that the sl added (geometry mode, display mode with the plane in the ones digit, alternative mode: whether the depth is absolute or incremental and the dwell in seconds or revolutions; omitted values mean the old behaviour):

| Cycle | Signature (the full sl signature of SINUMERIK 840D sl NC-Programmierung 06/2019, CNC-SW 4.92, section 3.25, cited "SW4.92 p.n"; D181) | Meaning |
|---|---|---|
| `CYCLE81` | `(RTP, RFP, SDIS, DP, DPR, DTB, _GMODE, _DMODE, _AMODE)` (SW4.92 p.1082-1083; `DTB` sixth, "Verweilzeit auf Endbohrtiefe") | drilling, centering: retract plane, reference plane, safety distance (unsigned, moving the reference plane forward towards the retract plane), depth absolute, depth relative to the reference plane and unsigned, counting away from the retract plane; identical planes, or a retract plane behind the reference plane, are alarm 61101 and give the reader no direction (D334), dwell |
| `CYCLE82` | `(RTP, RFP, SDIS, DP, DPR, DTB, _GMODE, _DMODE, _AMODE, _VARI, S_ZA, S_FA, S_ZD, S_FD)` (SW4.92 p.1083-1086) | drilling with dwell, counterboring; spot drilling and drilling through |

Calling: `CYCLE81(11, 6, 5, -50,)` once at the current position; `MCALL CYCLE81(11, 6, 5, -50,)` makes it modal: every following block with a position calls it (`X-113.333 Y-226.667`, `X0`, ...) until `MCALL` alone switches it off. `MCALL` works with any subprogram, and modal calls may not be nested. The modal call holds across program levels and is not scoped to one: only another `MCALL` replaces it and only a bare `MCALL` ends it, so a subprogram can arm it and return with it armed (D343). The modal subprogram also runs without a path motion when `S` or `F` is programmed while `G0` or `G1` is active, or when `G0` or `G1` stands alone in the block, so a bare `F` or `S` block between an armed `MCALL` and the next position drills an extra hole. The cycle feed is the modal `F` of `CYCLE81`, `CYCLE82`, `CYCLE83` and `CYCLE86` (the posts write `F.08` in the block before the `MCALL`); `CYCLE85` has its own `FFR`, `CYCLE830` its own `S_FB`, `CYCLE84` uses none and `CYCLE840` the modal `F` only with `ENC`=1 (D181, D380). A pattern cycle only describes the geometry of the hole arrangement: with no cycle armed the control reports 62100 "Kein Bohrzyklus aktiv", and after the message is acknowledged the pattern approaches the positions without calling anything, so the pattern and its modal cycle belong together (D259). The older 840D cycles have the same leading parameters without the mode integers, so `CYCLE81(RTP, RFP, SDIS, DP, DPR)` reads on both.

## 8. Variables, flow and subprograms

- `R1`..`R99` (more by machine data) arithmetic parameters, `R1=10`, `R[1]=10`, `X=R43`. They are a field of data type REAL and the number `<n>` is an INT from 0 to `MD28050 $MM_NUM_R_PARAM` minus one, written without leading zeros (`R0`, `R3`, `R10`), which is why a `[variables] map` entry is the template `Q = "R{index}"` and not a bare prefix (D173); global arithmetic parameters are the separate address `RG[<n>]`, written only with brackets, whose name comes from `MD15800` and whose count from `MD18156`, and in a synchronized action a channel R parameter takes a `$` (`$R10`); `DEF INT COUNT = 0`, `DEF REAL LEN`, `DEF BOOL`, `DEF CHAR`, `DEF STRING[32] NAME`, `DEF AXIS`, `DEF FRAME` in the definition part at the program start, one definition per block and one type per definition, the initialisation value optional with 0 as its default; a name must be defined before it is read or written (alarm 12550) and may not be defined twice (alarm 12200); a `DEF` is local to its unit; global user data (`GUD`) and the builder's variables (`GC1_XDREMI`, `XMW_1`) are declared outside the program.
- Operators `+ - * / DIV MOD` (`DIV` is the integer division, result type `INT`, `3 DIV 4 = 0`, which the reader writes as the NCX `INT(a / b)`; D346; no manual shows a negative operand, so the reader converts `DIV` only where both operands are number literals of 0 or more, or integer-valued literals of either sign whose quotient is exact, `-8 DIV 2 = -4`, and keeps any other `DIV` block `RAW` with the WARNING RDR506; D382), `==`, `<>`, `>`, `>=`, `<`, `<=`, `AND OR NOT XOR`, bitwise `B_AND B_OR B_NOT B_XOR`, `<<` string concatenation; functions `SIN COS TAN ASIN ACOS ATAN2 SQRT ABS POT TRUNC ROUND LN EXP MINVAL MAXVAL BOUND`, string functions. `ATAN2(y, x)` refers the angle to its second argument and gives it over four quadrants, above -180 and up to 180 degrees, which is exactly NCX `ATAN2` (D119).
- Jumps: `GOTOF LABEL` (forward), `GOTOB LABEL` (backward), `GOTO LABEL` (both), `GOTOC` (no alarm when the label is missing), `GOTOS` (program start), all also with `IF cond`; the target is a label `NAME:` at the block start or a block number of the same unit, which is why a `JUMP=END` of a subprogram cannot be a `GOTOF` and is written `RET("<end label>",,$P_STACK)` instead (D344); `CASE(R1) OF 1 GOTOF A 2 GOTOF B DEFAULT GOTOF C`; a computed target `GOTOF "STEP_" << I_STEP` (INDEX).
- Structures: `IF cond` ... `ELSE` ... `ENDIF`, `LOOP` ... `ENDLOOP`, `FOR R1 = 1 TO 10` ... `ENDFOR`, `WHILE cond` ... `ENDWHILE`, `REPEAT` ... `UNTIL cond`; program-part repeats `REPEAT LABEL P=3`, `REPEAT START END P=3`, `REPEATB LABEL P=3`, `ENDLABEL:`.
- Subprograms: `PROC NAME` (optional when there are no parameters) ... `RET` or `M17`; `PROC NAME(REAL LENGTH=10, INT N, VAR REAL RESULT)` with typed call-by-value parameters (defaults allowed, up to 127) and `VAR` call-by-reference; `EXTERN NAME(REAL, INT)` announces a subprogram with parameters in the caller; `PROC NAME SBLOF DISPLOF` suppresses single-block stops and the block display inside; `SAVE` restores the modal G codes at the return.
- Calls: `L100` (leading zeros count: `L0100` is another program; a call must stand in its own block, and the control resolves a name and an `L` number along the same search path, whose last steps are the user-, builder- and standard-cycle directories, so a builder cycle cannot be told from a subprogram of another file), `NAME` alone in its own block, `NAME(1, , 3)` with parameters (empty positions take the defaults), `NAME P3` three times, `MCALL NAME` modal, `CALL "NAME"` or `CALL VARIABLE` indirect, `CALL BLOCK "START" TO "END"`, `PCALL` with a path, `EXTCALL("path/NAME")` from an external drive, `ISOCALL` for an ISO program, `CALLPATH` extends the search path. `DEFINE NAME AS text` defines a macro.
- `STOPRE` stops the block preparation until the block is executed (needed before reading system variables that a previous block changes, and written before every restart label by the Monforts posts); `MSG("text")` shows a message on the screen (at most 124 characters in two lines of 62, and it stays until the next one), `MSG()` clears it, `MSG("text",1)` forces a main-run block of its own and interrupts continuous path; `SETAL(alarm)` raises an alarm; `WRITE`, `READ`, `DELETE`, `ISFILE` handle files.
- System variables: `$AA_IW[X]` workpiece position (a diameter under `DIAMON`, mapped one to one), `$AA_IM[X]` machine position (a radius by default, MD20360 bits 6/7 off, so the reader doubles it under `DIAMON` on an X axis programmed in diameter or switchable, unless `[[axis]] frames_in_diameter` is set, with the WARNING RDR510 until the factor is measured on a machine; D240), `$P_UIFR[n]` settable frames, `$P_PFRAME` programmable frame, `$P_TOOL`, `$P_TOOLNO`, `$TC_DP3[t, d]` tool length, `$P_SEARCH` (block search active), `$P_SIM` (simulation), `$AC_TIME`, `$A_DBB[n]`/`$A_DBW[n]` PLC bytes and words, `$AA_ETRANS` external shift. Machine and setting data `$MN_`, `$MC_`, `$MA_`, `$SC_`, `$SA_`.
- Synchronized actions: `ID=1 WHEN $AA_IW[X] > 100 DO M7`, `WHENEVER`, `FROM`, `EVERY`, `DO` with actions, `CANCEL(1)`; motion-synchronous and beyond the reach of a block-by-block reader: `RAW`.
- Interrupt routines `SETINT(1) PRIO=1 ASUP1`, `LIFTFAST` with `ALF` for a fast retract from the contour; `DISABLE`, `ENABLE`, `CLRINT`: `RAW`.

## 9. Several channels

- `INIT(2, "/_N_WKS_DIR/_N_SHAFT_WPD/_N_SHAFT2_MPF", "S")` selects a program in channel 2 (with synchronous acknowledgement), `START(2)` starts it, `WAITE(2)` waits for its end; `WAITM(1, 1, 2)` sets mark 1 in the own channel and waits until channels 1 and 2 have reached it (the previous block ends with exact stop; the mark is cleared after the synchronization); `WAITMC` brakes only when the others are not there yet; `SETM`/`CLEARM` set and clear marks without waiting (kept over reset). Marks 0..99, at most 10 set at once per channel; a single-channel system has mark 0 only. The own channel need not be listed.
- Axis exchange between channels: `RELEASE(X)`, `GET(X)`, `GETD(X)`, `AXTOCHAN`; `WAITP(X)` waits for a positioning axis. `RAW` in version 1.0.
- Multi-channel jobs on the control are a workpiece directory with one `MPF` per channel and a job list (`JOB` file); exported archives put the units into one file.

## 10. ISO mode

`G291` switches the control to its ISO dialect (Fanuc-compatible G-code with its own cycle set, `G290` switches back to Siemens mode); a machine that runs ISO programs is read with the Fanuc reader and the `dialect` of the machine file says so. Not to be confused with the ISO-style `CYCLE3xx` compatibility cycles of the Siemens cycle package.

## 11. Reading Siemens programs

1. Units: every `%_N_NAME_MPF` is a `PROGRAM`, every `%_N_NAME_SPF` and every `PROC` unit is a `SUB`; `;$PATH` lines are header comments; `_INI` units are `RAW` blocks of their own section.
2. Modality per G group with the source-side state; `G0`..`G3` verbs, `G90`/`G91` with `AC()`/`IC()` per word; `DC()`/`ACP()`/`ACN()` positions with the direction kept.
3. `T`, `M6`, `D` per section 5 and the machine's `[tool_change]` style; `S` and `M3` bind to the master spindle of the source-side state (`SETMS`), `S2=`/`M2=3` to spindle 2; the role comes from the machine file.
4. Frames: `ATRANS`/`AROT`/`AMIRROR` append, `TRANS`/`ROT`/`MIRROR`/`SCALE` cut the programmable entries of the chain first, which works where all of them stand after the last tilt of `CYCLE800`, whose system frame survives, and keeps the block `RAW` otherwise (D333); a new `CYCLE800` (`_ST` ones digit 0) resets the whole chain before its `TILT`, with `_X0`/`_Y0`/`_Z0` a `SHIFT` before it and `_X1`/`_Y1`/`_Z1` a `SHIFT` after it (D333); after a `CYCLE800` kept `RAW` the chain is unknown, so the frame blocks that depend on it stay `RAW` too (D333, D5); `G58`/`G59` are shifts; `CYCLE800` is `TILT` or `TILT_AXIS` with `MOVE` from `_DIR` and `_ST`, and a `RETRACT` block from `_FR`; the axis-wise orders and the spatial angles become `TILT`'s A, B, C through the rotation matrix (mode 27 exactly, with the angles reversed), the projection angles stay `RAW` (D335); `$P_UIFR` writes are `RAW`.
5. Cycles per section 7 into `CYCLE=` blocks with absolute coordinates along the drilling axis (`_AXN` is `AXIS`), the modal `F` before an `MCALL` into `CYCLE_F`, `MCALL` positions into `CYCLE_CALL`, `MCALL` alone into `CYCLE=OFF`, a direct call into `CYCLE=`, `CYCLE_CALL` and `CYCLE=OFF` (D224); patterns expand into calls. An `F` on a position block under `MCALL` of a cycle that takes the modal `F`, a literal or an expression, writes the `CYCLE` block again with that `CYCLE_F` before the `CYCLE_CALL`; the `F` stays the feed of the control (D387). A block with only `F` or `S` under an armed `MCALL` with `G0` or `G1` active calls the cycle at the position reached (SW4.92 p.540): its `F` or `RPM`, then the `CYCLE` block again where the `F` changes the `CYCLE_F`, then a `CYCLE_CALL`. A direct call inside an armed range leaves the `MCALL` armed (p.539): after its `CYCLE_CALL` the `CYCLE` block of the modal cycle stands again instead of `CYCLE=OFF`. An empty position takes the control's default, `VARI` of `CYCLE83` 0 (D164); a mode integer is read only where an entry fixes it: `CYCLE830` with the `_AMODE` ones digit 1 (absolute `_DP`) or 0 or omitted (incremental, `DEPTH` = `RFP` less \|`_DP`\|, D380), `SLOT1` and `SLOT2` with the `_DMODE` thousands digit 1 and `NUM` empty, 0 or 1, `SLOT1` with `RAD` and `INDA` empty or 0 and, in a direct call, `_CPA`/`_CPO` the position reached (D379). `MPIT` of `CYCLE84` and `CYCLE840` is the ISO 261 coarse pitch (D181); a `CYCLE840` with `ENC`=1 and a `CYCLE83` with `FDEP` or a `_DAM` other than 0 stay native. `_VRT` and `_DIS1` equal to `[cycles] chip_break_lift` and `peck_clearance` (or the control's own value where the key is left out) are carried by the machine (D358). Where a pattern cannot be expanded and stays `RAW`, the whole modal range stays `RAW` with it: the `F` before the `MCALL`, the `MCALL` block that armed the cycle and the `MCALL` alone that ends it, found by a look-ahead within the unit (D259).
6. Flow: structures are lowered to `LABEL`, `JUMP`, `IF`; a structure (`IF`/`ELSE`/`ENDIF`, `WHILE`, `FOR`, `LOOP`, `REPEAT`/`UNTIL`) whose condition or bounds have no NCX form stays `RAW` as a whole, its blocks with it, with a WARNING, and the `GOTOF` form of `IF $P_SEARCH OR $P_SIM GOTOF BEGINN` is the documented exception (D295); `REPEAT` forms to `REPEAT`/`TIMES` or `SUB` sections, a block range left where it stands and copied into a `SUB` named `REPEAT_<first label>_<last label>` behind the program (D327); `PROC` parameters to `ARG` names; `M17`/`RET` to `SUB=END`; `M30`/`M2` to `PROGRAM=END`. `GROUP_BEGIN` with a literal `_MODE` whose bit 1 is clear is `SECTION` with its name; `GROUP_END`, `GROUP_ADDEND` and the `DEFINE ... AS` line are comment-only lines holding their text (D291). A call is `CALL` only where the file holds the unit, `EXTERN` announces it or `CALL "name"`/`EXTCALL` names it; any other target, `L` numbers included, is `RAW` (rule 8, D293).
7. `WAITM` to `SYNC` with `WITH`; `INIT`/`START`/`WAITE` to the channel words.
8. `GROUP_BEGIN` with `_MODE` bit 1 set (automatic retract to the tool-change point) or a `_MODE` that is no literal number (D291), `STOPRE`, `WORKPIECE` (the blank stays `RAW` although a `STOCK` word exists, because the control's forms carry shapes and arguments the word does not, D352), `DEF` of the non-numeric types `CHAR`, `STRING`, `AXIS` and `FRAME` (D261), an `MSG` that `MESSAGE` cannot carry (D326), synchronized actions, interrupts, `ORI*` and the path-control words, and every call target the file, `EXTERN` and the configuration do not know, a builder cycle and an `L` number outside the file among them (D293): `RAW` with a WARNING, kept in place. The modal call is one channel state that holds across program levels, so a subprogram a `RAW` line calls can leave one armed after its return: after a `RAW` line the modal call is unknown, as the G groups are, and the compiler writes `MCALL` alone before the next motion (D343).
9. Numbers as written; `=` and extensions parsed per section 1; expressions as values become NCX expressions. One exception (D292): a feed under `G70`/`G71` whose unit differs from `base_units` is converted from the basic system into the unit `UNITS` names, `F254` under `G70` on a metric machine is `F=10`, with the WARNING RDR507 naming the code; `G700`/`G710` feeds are taken as written. The control keeps the physical feed across a switch of group 13 (Funktionshandbuch Grundfunktionen 2012 p.342), so where a switch changes `UNITS` the reader converts the modal feed into the new unit and writes it on the next feed motion, with RDR507, and warns where it does not know that feed.

## 12. Writing Siemens programs

1. One output file per NCX file with the `%_N_NAME_MPF`/`_SPF` headers when `program_layout = "one_file"`, else one file per unit; `PROC NAME` at the top of every subprogram and `RET` (or `M17`, `sub_end`) at its end; `M30` (`program_end`) at the program end, behind the label a `JUMP=END` reaches; a `JUMP=END` inside a subprogram is `RET("<that label>",,$P_STACK)`, and the label stands in every program that reaches the subprogram (D344).
2. `=` after every multi-letter address and extension; `I=AC()` for absolute centers, `CR=` for the `R` form, `TURN=` for sweeps beyond a turn (or split into turns when the target is an older 840D). `G0` to `G3` stand on every motion block, the Siemens family value of `[format] motion_code`; "change" and "arcs" are the other forms (D299).
3. `T="NAME"` or `T1` and `M6` per `[tool_change]`, `D` from `OFFSET`, `D0` where the block sets `OFFSET:LEN=0` (D301); `SETMS(n)` in its own block when the master spindle changes; `S<n>=` and `M<n>=3` for the other spindles. A spindle template's group-15 code is written as the code for the feed type the block leaves, `G96` under the feed per revolution and `G961` under the feed per minute, and a `FEED_MODE` change under the surface speed as that code alone; the control also has `G962` and `G972`, which leave the feed type untouched (D300).

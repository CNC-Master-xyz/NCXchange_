# Decisions

Every decision that shaped the specification, numbered as the documents cite them (`D31`, `D48`, ...). The numbers are stable: a decision that was replaced keeps its number and says by what. The questions, the recommendations and the maintainer's answers behind most of them are in `rationale.md`; the specification documents in `../spec/` carry the decisions in their text.

Status: version 1.0 of the documentation set, 2026-09-12, extended 2026-09-11 by the fourth round (D90 to D106) from the implementation plan, with follow-up clarifications on 2026-09-12 and 2026-09-13, and D107 from its final review on 2026-09-13. Nothing is open. New decisions get the next number and a row here, and the document sections they change are updated in the same commit.

| D28 | The VM stores radii; `DIAMETER` says how the NCX X words are meant; the X axis `programming` of the source and target machine says what is read and written, and D60 says which words convert. | 2026-09-11 |

| D30 | Machine axis names are allowed in programs. Siemens writes `Z2=450`; Fanuc 30i/31i writes extended axis names the same way (`C2=`, `H2=`, verified in the Nakamura manual); `letter` in the `[[axis]]` table carries the form. | 2026-09-11 |
| D31 | Frame transforms compose in program order: `SHIFT`, `ROTATE`, `MIRROR`, `TILT` are applied to the frame active where they stand and appended to a chain; `RESET` cuts the chain at that kind, `ORIGIN` empties it; readers translate replacing controllers (Fanuc `G52`, Heidenhain cycle 7, Siemens `TRANS`) into reset plus word, compilers write the chain in the same order. Replaces the absolute model of D46. The common order is origin, shift, then tilt or rotate; a shift after a tilt is a different program and stays one. | 2026-09-11 |
| D33 | Fanuc `#100` is `V100`. | 2026-09-11 |
| D34 | Writers emit a complete header; configuration defaults apply to source readers only. | 2026-09-11 |

| D37 | `ExpandCycles` VM option for analytics. | 2026-09-11 |
| D38 | Reading an unassigned variable is an ERROR by default (`unassigned = 0` per machine file). | 2026-09-11 |
| D39 | The job scheduler is round based; time only inside the timeline analytics. | 2026-09-11 |
| D40 | Workpiece transfer detection is modular per machine: the `[workpiece]` table first, the chuck function rule second, a reader rule from a plugin for machines whose M codes run hidden subprograms. Nothing is assumed to be the same across machines of one manufacturer. | 2026-09-11 |
| D41 | Resource types in 1.0: work spindle, tool spindle, tool holder, table, axis; bar feeder, tailstock, steady rest and pallet changer are named functions. | 2026-09-11 |
| D42 | A different tool preloaded than called is a WARNING, never an ERROR: the user may have preselected a special pocket on purpose. | 2026-09-11 |
| D43 | The canonical word order is mandatory for `ncx format` and all writers; hand-written files are free. | 2026-09-10 |
| D44 | Incremental coordinates are per-value words (`IX`), no modal switch. | 2026-09-10 |
| D45 | Cycles beyond the built-in drilling family come from a per-controller cycle catalog; native cycles may be written as `CYCLE:CONTROLLER=n`. | 2026-09-10 |
| D46 | Transforms are absolute words that replace their own kind (`SHIFT`, `ROTATE`, `MIRROR`, `TILT`); additive source forms are folded by the reader. | 2026-09-10 |
| D47 | Tool change is two words: `PRELOAD` prepares, `TOOL` changes; `TOOL` without value changes to the preloaded tool; the compiler chooses the machine's form. | 2026-09-10 |
| D48 | File structure: `FILE=BEGIN NCX=1` ... `FILE=END` holds one or more `PROGRAM=BEGIN` ... `PROGRAM=END` sections and any number of `SUB=BEGIN NAME=` ... `SUB=END` sections; `PROGRAM=END` triggers what `program_end` in the machine file says (M30, M2, M17); there is no `EXIT`. Several programs per file are what Siemens job archives and Fanuc multi-program files already are. | 2026-09-12 |
| D49 | A source `M2` is not preserved; `program_end` in the machine configuration decides, readers accept both. | 2026-09-11 |
| D50 | Revised 2026-09-12 by D48: `PROGRAM=END` is the executed program end (M30, M2 or M17 per machine configuration; NCX does not distinguish); an early end is `JUMP=END`; sections a source keeps below its `M30` stand in front of `PROGRAM=END` behind a `JUMP=END`. The draft 2 `EXIT` word is gone. | 2026-09-10 |
| D51 | System variables are reserved `SYS_` names with an optional index and a per-controller mapping. | 2026-09-11 |
| D52 | Tool change macro parameters by placeholders with look-ahead (`{next}`, `{b}`, `{c}`) and the tool kind from the tool table. | 2026-09-11 |
| D53 | `SKIP` blocks are executed by default (run option `skip_blocks`). | 2026-09-11 |
| D54 | `CYLINDER`, `POLAR`, `TCPM` are state words; geometry only in the kinematics module. Refined 2026-09-11 by D102: under `POLAR` and `CYLINDER` the VM keeps the position in the transformed plane and resolves `ARC` and `COMP` there; the Cartesian workpiece position stays with the kinematics module. | 2026-09-11 |
| D55 | `SETPOS` is a verb of its own; the VM records a per-axis shift cleared by `ORIGIN`. | 2026-09-11 |
| D56 | Channel binding of functions lives in the configuration (`channel`, `channels = "all"`); the job compiler moves or duplicates the words. | 2026-09-11 |
| D57 | Under `WORKPIECE=SUB` coordinates are in the holder's own frame; `SUB_frame` in the configuration says mirror or datum, for the reader (source machine) as for the compiler. | 2026-09-11 |
| D58 | Chamfers and roundings are expanded by readers; no words for now. | 2026-09-11 |
| D59 | Drilling axis on lathes as `AXIS` on the cycle (the shop-floor terms for the two cases: axial and radial cycle). | 2026-09-11 |
| D60 | `DIAMETER` halves `X`, `IX`, absolute `CENTER:X` and the X words of an `AXIS=X` cycle; other radial distances are radius values; `programming` on the X axis decides what is read and written. Verified for Heidenhain turning (TNC 640: X diameter values, radial infeed radius values). | 2026-09-11 |
| D61 | Plugins rewrite the program or the output, never the VM state. | 2026-09-11 |

| D66 | Folding an expanded source sequence back into one word is the job of a reader rule (plugin or configuration), not of a generic multi-block matcher in the core. | 2026-09-11 |
| D67 | Analytics in 1.0: segment length and tool vector change, tool list, runtime estimate; every analytic takes a block range (`--from`, `--to`). | 2026-09-11 |
| D68 | Siemens stays a family of 1.0 with generic Sinumerik; GILDEMEISTER structure programming (L cycles, `TC`, `WAITM` templates) is documented but not implemented for now, and no decision may prevent it later. | 2026-09-11 |
| D69 | Okuma OSP and Mazatrol are out of scope for 1.0; Mazak EIA programs serve as Fanuc-family test inputs. | 2026-09-11 |
| D70 | The sample folders get a quick survey for missing words now and serve as the reader test corpus later. | 2026-09-11 |

| D81 | 5-axis motion by tool vector: `LINE` under `TCPM=ON` may carry `TX TY TZ` (tool direction) and `NX NY NZ` (surface normal) instead of rotary words; the VM stores them unresolved, the kinematics module converts; more vector forms may follow. | 2026-09-12 |
| D82 | `TILT_AXIS A= B= C=` is the tilted plane by rotary axis positions (`PLANE AXIAL`, cycle 19, `CYCLE800` rotary mode, `G68.1`); `MOVE=TURN\|MOVE\|STAY` and `ROT=TABLE\|COORD` are the positioning options on both tilt forms; readers keep the source form, compilers convert only with the kinematics module. | 2026-09-12 |
| D83 | `RETRACT` is a motion verb: bare to the tool-axis limit (`M140 MB MAX`), with a value by that distance; a computed machine-frame move where the kinematics is known, else an ERROR at compile time. | 2026-09-12 |

| D86 | `ROTARY_PATH=SHORTEST\|FULL` and `ROTARY_FEED=MM_MIN\|DEG_MIN` are modal words (`M126`/`M127`, `M116`/`M117`); the other TCPM options and `G41.2` stay `RAW`. | 2026-09-12 |
| D87 | The cycle word `RETRACT` is `CYCLE_RETRACT`; `RETRACT` is the motion verb. A cycle word that clashes with a motion word always gets the `CYCLE_` prefix. | 2026-09-12 |

| D89 | Subprograms are `SUB=BEGIN NAME=` ... `SUB=END` sections of the file next to the programs; jump-entered sections of a source stay inside their program in front of `PROGRAM=END` behind a `JUMP=END`. | 2026-09-12 |
| D90 | The canonical order is an explicit rank table in the word catalog: the buckets of language 5 rule 6 with a fixed inner order (`SKIP` and the structural words first; machine axes alphabetical after `X Y Z A B C`, absolute before incremental; `CONTOUR` a cycle word); `spec/generated/word-catalog.md` is the reference. Rule 6 no longer refers to the machine configuration. The EBNF line for `sub` accepts an identifier, an integer or a string after `NAME=`; `DIAMETER` keeps its row in 4.2 and 4.11 refers to it. The ten example blocks and the snippets of language 6 were rewritten into the rank order by hand when the decision was applied; from P0-06 on `ncx format` reproduces the examples byte for byte. | 2026-09-11 |
| D91 | `ncx format` is the parser and the canonical writer only: no machine file, no virtual machine, no expander; a bare `TOOL` stays bare. Revises D18 (`format` leaves the STATIC list) and D27 (the compilers write the number, not `format`). | 2026-09-11 |
| D92 | Comment-only lines and blank lines are trivia, kept in place and written back as read, allowed before `FILE=BEGIN` and after `FILE=END`; a block keeps its trailing comment; the canonical layout puts the semicolon in column 57, or three spaces after the words when they end at column 54 or later. | 2026-09-11 |
| D93 | A key of the form `[XYZABCUVW][0-9]{0,2}`, or `I` plus that, that is not a catalog word is a machine axis word for the parser, with a number or expression value (bare under `HOME`), in a block whose verb takes axis words and that carries no `CYCLE:<controller>=n` (D94); the virtual machine resolves it against `[[axis]]` (no entry: ERROR with a machine file, the D103 WARNING without one); in the canonical order machine axes sort alphabetically after `X Y Z A B C`, independent of any machine file. | 2026-09-11 |
| D94 | In a `CYCLE:<controller>=n` block, keys the catalog does not know are native parameters, kept in source order after the cycle words; a compiler for another family reports the block as an ERROR like `RAW`. | 2026-09-11 |
| D95 | `@SAVE` and `@RESTORE` are lexed only under the expander's parser option; their value is a state key `KEY[:ADDR]`; in a user file a word starting with `@` is the ERROR "pseudo-word in a user file". | 2026-09-11 |
| D96 | `CYLINDER=30` switches the cylinder surface transformation on with the reference radius as its value, `CYLINDER=OFF` switches it off; there is no `ON` form; the key `R` belongs to arcs only; the `CYLINDER_ON` templates keep `{r}`, which is that value. | 2026-09-11 |
| D97 | Exit codes for every command: 0 no ERROR; 1 an ERROR, or a WARNING under `--strict`, or `format --check` with a difference; 2 a usage error, an unreadable input or a missing required machine file. | 2026-09-11 |
| D98 | Diagnostic codes are an area prefix and three digits (`PAR`, `VM`, `CFG`, `RDR`, `CMP`, `ANA`, `PLG`, `CLI`), constants in one `DiagnosticCodes` class per project, rendered `file(line): ERROR VM042: message`; severities ERROR, WARNING, INFO (INFO for notes that are neither, such as a plugin's inserted blocks); a diagnostic on a generated block carries the originating line in `OriginLine`, rendered `file(line, from 12)`. | 2026-09-11 |
| D99 | STATIC mode follows `CALL`s: a subprogram is walked at every call with the caller's state, a `CALL` with `TIMES=n` n times in sequence, within the configured call depth; a `CALL` of an external program is not followed (the position becomes unknown); a subprogram nothing calls is walked once from a default entry state (units, workplane, diameter, feed mode from the first program's first verb; position unknown) with the caller-dependent validations suppressed. Compilers write each `SUB` once (once per calling program where the target needs it, Heidenhain) from an unknown target state; walks that would write different lines are an ERROR. `trace` writes one row per walk, `annotate` the first walk. Clarified 2026-09-11 and 2026-09-13. | 2026-09-11 |
| D100 | `HOME` on an axis without a reference point is a WARNING at check time, once per run and axis, and the axis is unknown in every frame afterwards; the ERROR belongs to a compiler that must write the coordinates. Every `[[axis]]` carries `home` and `limits` in machine coordinates (the G53 / M91 frame); a `[positions]` table names further machine-frame positions (`tool_change`, `program_end`, ...) that expansion rules reach through `{position:NAME}`; no new NCX word. At program start an axis with `home` is known in the MACHINE frame at that reference point and unknown in the workpiece frame, as in version 1.0 (clarified 2026-09-13). | 2026-09-11 |
| D101 | `SETPOS` needs the axis known in some frame; known in the MACHINE frame only, the shift is recorded against the machine position (newSetposShift = machinePos minus declared) and the axis becomes known in the workpiece frame with the declared value. Clarified 2026-09-12: directly after a `HOME` of that axis that found no reference point (D100), `SETPOS` is accepted as well; the axis becomes known in the workpiece frame with the declared value and its machine position stays unknown. The ERROR remains for every other axis unknown in every frame. How long "directly after" lasts is D127. | 2026-09-11 |
| D102 | Under `POLAR=ON` the working plane for `ARC` and `COMP` is the face plane of the X word (a diameter under `DIAMETER=ON`) and the C word as a Cartesian length; under `CYLINDER=n` it is the plane of the cylinder axis (Z on a lathe) and the C word as a length on the circumference. The position is known in that plane from the first motion under the transformation and unknown in the workpiece frame; after the transformation is switched off it stays unknown there until the next motion with known coordinates. Arc direction: X then C onto the face (`G12.1`, `TRANSMIT`), the cylinder axis then C on the developed surface (`G7.1`, `TRACYL`), independent of `WORKPLANE`. Refines D54. Clarified 2026-09-13. | 2026-09-11 |
| D103 | Without a machine file, `check`, `trace`, `annotate` and `analyze` run against a built-in default machine (spindle `MAIN`, holder `TOOL`, axes `X Y Z A B C`, coolant `STANDARD`); an unknown role, function or machine axis is then a WARNING "not checked: no machine file"; `convert` and `compile` keep requiring a machine file (D77). A work spindle created on the spot gets a rotary axis of its own, so `C` resolves to it while it is the workpiece holder (clarified 2026-09-13). | 2026-09-11 |
| D104 | `millturn1.toml` is the fifth example machine, a generic SINUMERIK 840D sl mill-turn without builder cycles (roles `MAIN` = `S1` with axis `C`, `SUB` = `S2` with axis `C2`, `TOOL` = `S3`, `TURRET1` = `H1`; axes `X Y Z C Z2 C2`; functions `SUB_CHUCK`, `MAIN_CHUCK`; numeric tools `T{tool} D{offset}`; `COUPON`/`COUPOF`; `[workpiece] SUB_frame = "datum"`); `MILLTURN_TRANSFER.ncx` checks and compiles for it (P2-04, P5-02); `dmg-ctx-840d.toml` stays the documentation of the structure programming (D68). | 2026-09-11 |
| D105 | Function values in the machine file are strings; a bare integer is accepted and means `M` followed by the number. The loader normalizes every M or G code to its spelling without leading zeros (`8`, `08`, `M8`, `M08` become `M8`; `G01` becomes `G1`), the compiler always writes that form, and readers compare codes by number. | 2026-09-11 |
| D106 | An interface lives with its caller together with the types its method takes (`IProgramRewriter`, `IVmListener`, `RewriteResult` and the `RewriteContext` abstraction in `Ncx.Core`; `ISourceRule` in `Ncx.Readers`; `IBlockWriter` in `Ncx.Compilers`); `Ncx.Plugins` holds the loader, the concrete `RewriteContext` built from the D80 settings (machine name, channel, line, settings, no VM) and the diagnostics helpers, and references Core, Readers and Compilers, so a plugin references `Ncx.Plugins` alone; the plugin load context shares the `Ncx.*` assemblies with the host; D61 means no mutation. Clarified 2026-09-13. | 2026-09-11 |
| D107 | The typed records of the machine file and of the job manifest (`MachineConfig` and its tables, `JobManifest`) live in `Ncx.Core`, namespace `Ncx.Core.Machine`, so that the virtual machine, the expander and the job scheduler read them without depending on `Ncx.Config`; the records keep template values as text. `Ncx.Config` keeps the Tomlyn loader, the templates (parsed from that text, with render and match), the cycle catalog and job manifest loading and the `DefaultMachine` of D103. | 2026-09-13 |
| D118 | `ATAN2` takes two arguments, `MIN` and `MAX` two or more, every other function one (`ROUND` has no decimals argument); a call with another number of arguments is an ERROR of the expression parser, `PAR111`, like an unknown function, so `format`, `convert`, `check` and `compile` all report it. The evaluation code `VM904` is gone, and its number is not reused. | 2026-10-01 |
| D119 | `ATAN2(y, x)` takes the ordinate first and is the angle of the point `(x, y)` from +X, above -180 and up to 180 degrees, as Siemens `ATAN2()` gives it; Fanuc's two-argument `ATAN[y]/[x]` has the same argument order but gives 0 to 360 degrees unless bit 0 (`NAT`) of parameter 6004 is 1, so the Fanuc reader and compiler convert the range once the machine file says which range the control uses. `FRAC(x) = x - INT(x)` keeps the sign of `x`, so that `INT(x) + FRAC(x)` is `x`, as the TNC's `FRAC` beside its truncating `INT` does. A function without a real result is an ERROR, as division by zero is: `ATAN2(0, 0)`, `SQRT` of a negative number, `LN` of zero or less, `ASIN` or `ACOS` outside -1 to 1, `TAN` of 90 and 270 degrees. | 2026-10-01 |
| D122 | In the `CENTER` form of `ARC`, start = end is compared exactly, on the plane coordinates as the position store holds them (D121): an end that lies within the arc tolerance of the start is the short arc, or the near-full turn, its coordinates and the direction give, never a full circle. A `CENTER` that lies on the start point (radius 0) is an ERROR, `VM235`, as `R=0` already is. | 2026-10-01 |
| D127 | The `SETPOS` permission of D101 after a `HOME` that found no reference point lasts until the next block that names the axis (a motion, a `HOME` or a `SETPOS` with it), or that switches the spindle owning the axis to `SPINDLE` mode; blocks that touch neither may stand between the `HOME` and the `SETPOS`, so a reader need not keep `G28 H0` and `G50 C0` adjacent. | 2026-10-01 |
| D131 | The `C=` rule of VM 3.8 rule 4 covers every word that positions the spindle's axis or declares its position: `C` and `IC` under `RAPID`, `LINE`, `ARC`, `CYCLE_CALL` and `SETPOS`, the bare `C` of `HOME`, and the `C` of a `TILT_AXIS` with `MOVE=TURN` or `MOVE=MOVE`. `SHIFT` and `TILT_AXIS` with `MOVE=STAY` are not covered: they move nothing. | 2026-10-01 |
| D147 | Only the standard rotary name whose letter the current workpiece holder's rotary axis carries (the axis's NCX name without its digits, `C2` gives `C`) resolves to that axis; every other `A`, `B` or `C` resolves through `[[axis]]` by its NCX name, so the Mori Seiki `A` ejector slide and the swivel `B` of the Mori, DMG, Doosan and Nakamura keep their own axes. | 2026-10-01 |
| D163 | Heidenhain cycle 200 with `Q211`=0 is `DRILL` and with any other `Q211` is `DRILL_DWELL` with `CYCLE_DWELL`=`Q211`; cycle 203 with `Q213`=0 retracts fully after every infeed and is `PECK`, and with a `Q213` of at least the number of infeeds, `ceil(|Q201| / Q202)`, it never retracts and is `CHIP_BREAK`, while a `Q213` between the two is the mixed form, read natively as `CYCLE:HEIDENHAIN=203` (D94). `Q256` tells the two apart on no control, so the `203 with Q256` of controller-mapping 5 was wrong. These are rules of the Heidenhain reader and compiler, not fixed values; the compiler writes `Q211` = `CYCLE_DWELL` or 0, and `Q213` 0 for `PECK` and the number of infeeds for `CHIP_BREAK`. | 2026-10-01 |
| D168 | `AND` and `OR` do not short-circuit: both operands are evaluated, left to right, as for every other operator, and the first ERROR stops the run; a guard against a division by zero is written as two blocks. | 2026-10-01 |
| D171 | `syncPartner` and `syncPhase` stand on the following spindle only, naming the leading spindle and carrying the phase; the leading spindle keeps neither, so that VM 3.8 rule 5 knows which spindle follows. | 2026-10-01 |

## How the set came to be

The language, the virtual machine, the machine configuration and the controller mapping were drafted in eight rounds between 2026-09-10 and 2026-09-12: a first rewrite around bare words and explicit motion verbs, the separation of program end and file end, two rounds against the machine-builder manuals (Nakamura, Mori Seiki, DMG MORI, Doosan, Biglia), the maintainer's notes on diameter programming, runtime estimation and machine sequences, and three rounds of answered questions, the last two of which added the Siemens column from the SINUMERIK 840D sl manual and the words for 5-axis programs found in the sample corpus. The architecture outline and the code guidelines followed the specification. Version 1.0 is the state handed over to this repository; from here on the documents change with the code. A fourth round of seventeen questions came 2026-09-11 from reading the set against the examples before the first code (`../implementation/01-findings.md`); they were answered the same day.

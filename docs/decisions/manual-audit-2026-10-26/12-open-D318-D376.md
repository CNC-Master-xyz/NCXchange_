## Before the entries: the October question (iTNC 530 indexed TOOL CALL)

**The record is wrong to say the library lacks the iTNC 530 Technisches Handbuch.** The connector holds "iTNC530-HSCI Technisches Handbuch NC-SW 60642x-04" (2014, 1986 pages). What it says:
- **The macro replaces the T-strobe.** The tool-change program (TC= in NCMACRO.SYS) is called during a TOOL CALL in place of the T-strobe (p.1251, p.1609). With no entry in NCMACRO.SYS, the TOOL CALL runs without the macro (p.1610).
- **MP7480.0 decides when the number goes out.** Its settings choose between output "only on a tool-number change" (1/3/5) and output "at every TOOL CALL" (2/4/6) (p.1614).
- **Number and index are separate parameters.** The index is passed in W266 (p.1600). The macro example has to read both and re-send them as TOOL CALL Q1 .Q7 (p.1610–1611).
- **The macro can tell the tool is already in the spindle.** FN18 ID61 returns a change sequence, and value 0 means exactly that (p.1736).

**Verdict: narrowed, not settled.** No page says whether 5 → 5.1 counts as a tool-number change, or whether the macro is skipped when MP7480.0 suppresses the strobe. Unlike the TNC 640's rule by block content, the iTNC 530 outcome depends on the builder's MP7480.0 and macro.

For comparison, the TNC 640 TH 34059x-08-SP01 p.60 describes "precautionary" TOOL CALLs to the same tool. They trigger a sister-tool change only if the block carries a name, a number or a tool-axis direction, which matches the Klartext rule.

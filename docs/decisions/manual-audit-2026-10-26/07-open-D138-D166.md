**D151 (maintainer's answer, 2026-10-07) — FACT WRONG in part; partly newly settled**
- `CYCLE832(<S_TOL>,<S_TOLM>,<S_OTOL>)`, and S_OTOL must be programmed, = 1 on 3-axis machines. CONFIRMED:
  - SW492 p.1125-1126 (the table text is garbled there),
  - clean wording in 840D sl Programmierung BS.000508 p.106,
  - English SW494 p.1113.
  - So the proposed `ON = "CYCLE832({tol},{mode})"` is invalid, as the September answer says. Use `CYCLE832({tol},{mode},1)`.
- Tens digit 1, _ORI_FINISH = 11 and so on; deselection `CYCLE832(0,0,1)` or bare `CYCLE832()`. CONFIRMED, SW492 p.1127-1128.
- New, version dependence: BS.000508 p.108 says the CYCLE832 syntax changes between software levels.
  - Up to SW 7.5 it has only two parameters (Toleranz, Technologie).
  - From Operate 2.6 the third parameter is a version identifier.
  - From SW 4.5 the third parameter is the ORI tolerance.
  - With an ORI tolerance, ORISON may have to follow CYCLE832, depending on CUST_832.
  - Consequence: ON_ROTARY on Siemens may need a trailing ORISON, and the 3-argument ON is wrong on pre-Operate 840D. Both belong in the machine file and should be noted.
- TA = 0 or NO ENT makes the control use the manufacturer's value. CONFIRMED for TNC 640 only, Zyklen p.373.
- iTNC 530: TA range 0 to 179.9999, and the only example is `32.2 HSC-MODE:1 TA5`. CONFIRMED, 340490-07 p.316.
- NEWLY SETTLED, mostly: the maintainer left open whether the iTNC 530 accepts cycle 32 without TA. Two passages decide most of it:
  - iTNC 530 Zyklen 340490-07 p.315: when a program with cycle 32 carrying only the tolerance T is read in, the TNC inserts the two missing parameters (HSC-MODE, TA) with the value 0. A T-only cycle 32 is therefore accepted, and a missing TA becomes TA0.
  - iTNC 530 NC-Fehlermeldungen (2003) p.309, alarm 6066 "Drehachstoleranz nicht erlaubt": raised when cycle 32 programs a rotary-axis tolerance while the HSC filter (MP1094) is inactive.
- What this changes in the September advice to "write TA0 rather than dropping TA": on the iTNC 530 that advice has no support. The zero fallback is documented only for the TNC 640. On a three-axis iTNC without the HSC filter, any written TA risks alarm 6066. The safe iTNC `ON` is T-only, or no TA at all.

**Answers that would change**
- **D151:**
  - Siemens `ON` must carry a third argument of 1.
  - Note the version dependence (two-parameter CYCLE832 up to SW 7.5) and a possible ORISON after `ON_ROTARY`.
  - The open iTNC question is mostly settled: the control fills a missing TA with 0. Drop the September "write TA0" advice for the iTNC 530, because alarm 6066 forbids a rotary tolerance without the HSC filter.
- **D159:**
  - The key must be a time increment, not "ms"/"s".
  - The compiler must write X/U with a decimal point.
  - The Mori NL series accepts P with a decimal point.
  - Whether the cycle P follows the same setting is still open.
- **D164:** add Q395 (default 0) as an unfilled position for TNC 640 cycles 200 and 203. Do not cite uc.com as a runtime-default precedent.
- **D157:** the Heidenhain rule must be conditional (Q204 > Q200), as the September answer already says.
- **D145:** a non-integer index rounds; it is not an error, as the September answer already says.

Pure citation fixes are needed in D139, D142, D143, D145, D150, D157, D159 and D162.
